### 0.3 木纹：第一版是"假木纹"，已降级为抽象

这是本次最重要的修正。我把成品图放大到 1:1 并做**对比度拉伸**（把 ±6 级拉伸到全动态）后，发现第一版的木纹结构站不住：

| 缺陷 | 具体表现 |
|---|---|
| 平行带间距与宽度过于均匀 | 像印刷贴皮，不像木头 |
| 带子边缘发虚起泡 | 低分辨率上采样留下的痕迹，读起来像拉丝/颗粒漆 |
| 带内一层海绵状斑点 | 既不像木纤维也不像纸 |
| 完全没有沿纹理方向的纤维感 | 只有平滑波纹，缺"木头之所以是木头"的那个方向性 |

**在这条上我认定它不合格，按你给的底线直接降级为抽象路线**，没有试图靠加细节去"救"它——因为 ≤5% 对比度下细节做不出来，硬做只会更像贴皮。

现在的做法（§2.1 有完整分层）：
- **不做**节疤、年轮、导管孔、纤维 streak
- **做**两件事：①**各向异性低频色块**（纵向采样密、横向采样疏 → 竖条状柔和色块，这是木纹在低对比度下的抽象形态）②**极淡的长周期平行纹理**（750 宽只有 5~6 条，幅度 ±2 级）
- 纹理总对比度 **3.76%**（比第一版 4.36% **更低**，没有偷偷提高）

### 0.4 光斑有一个数学上限，需要你接受

你要"光斑是灵魂、够大够柔"。实测结果：**亮暗差最大只能做到约 14 级（5.9%）**，原因是硬约束卡死：

- 平均色必须锁死 `#F6E9D4` → R 通道基色已 **246**，距 255 只剩 **9 级**余量
- 光斑再亮就会把 R 烧成死白（实测加到某个程度后，R≥253 的像素占比从 0.29% 涨到 2.43%，高光区反而**因为压平而对比更低**）

我扫了 4 组参数（详见 §2.1 实测表），最好的一档是 **13.6 级**、R 撞顶像素仅 **0.29%**（无可见死白）。若要更戏剧化的光柱，只能二选一：**改基色**（比如把桌面压到 `#EFE0C6`，但那偏离 6.5 定的色值）或**允许 R 区烧白**（会变成一块死白，显廉价）。**我选了最保守的一档。**

## 2. 三张主图：规格与实测

### 2.1 `home_bg_desk.png` — 晴日书桌

**分层结构（单层交付，内部 5 层合成，每层参数都可单独调）**

| 层 | 内容 | 幅度 | 脚本参数 |
|---|---|---|---|
| L1 各向异性色块 | 纵向细、横向粗的低频噪声（3 octave）→ 竖条状柔和色块 | ±2.5 级 | `TONE_AMP` |
| L2 极淡平行纹理 | 长周期正弦 + 弯曲 + 疏密调制 | ±2.0 级 | `GRAIN_AMP` / `GRAIN_PERIOD` / `WARP_CELLS` |
| L3 极淡噪点 | 3~6px 尺度，只防"塑料感"，不承载造型 | ±1.2 级 | `FIBER_A` |
| L4 阳光光斑 | 中心放在**画面外侧**（左上角外），只让衰减落入画面 → 永远看不到可见圆环 | R 被软膝收住，主要抬 G/B | `SUN_AMP` |
| L5 四周压暗 | 从归一化半径 0.60 起，只压最外圈 | 最外圈 −12 级 | `VIG_AMP` / `VIG_START` |

**实测指标**

| 项 | 要求 | 实测 | 结论 |
|---|---|---|---|
| 尺寸 | 750×1624 | 750×1624 | ✅ |
| 平均色 | `#F6E9D4` | **精确 #F6E9D4**（末级整数微调锁定） | ✅ |
| 纹理对比度 | ≤5% | **3.76%**（大尺度 5.0 级 + 平行 4.0 级，合计峰谷 8.7 级） | ✅ 比第一版更低 |
| 全幅明度 | — | 218–239（21.7 级 / 9.41%），含光斑与压暗 | 见 0.4 |
| 光斑亮暗差 | "光斑是灵魂" | 亮区 **235.8** → 画面中心 **231.0** → 右下角 **222.2**，差 **13.6 级 / 5.9%** | 已达数学上限 |
| R 通道撞顶 | 不能有死白 | R≥253 的像素仅 **0.29%** | ✅ 无可见死白 |
| 光斑有无硬边 | 不要明显圆 | 沿 3 条射线采样均为单调下降，无回升（无环） | ✅ |
| 具体物件 | 不能有 | 无 | ✅ |
| 中下部留白 | 大面积 | 纹理由上到下连续，无视觉焦点 | ✅ |

**4 组光斑参数扫描（证明 13.6 级已是上限）**

| 方案 | SUN_AMP | VIG_AMP | 亮暗差 | R≥253 占比 |
|---|---|---|---|---|
| **A 采用** | (8.0, 12.5, 12.0) | (12.0, 11.2, 9.8) | **13.6 级** | **0.29%** |
| B 偏暖+重压暗 | (9.0, 12.0, 3.5) | (16.0, 15.0, 13.0) | 12.3 级 | 1.41% |
| C 中度 | (9.0, 14.0, 8.0) | (14.0, 13.0, 11.0) | 13.7 级 | 1.13% |
| D 更暖更压 | (9.5, 13.0, 2.0) | (18.0, 17.0, 14.5) | 12.8 级 | 2.43% |

> 结论：加大光斑会同时抬高"零均值"补偿量，**亮暗差几乎不涨，但死白面积成倍涨**。B/C/D 都比 A 差。这不是没调够，是色值约束决定的。

**用法**：全铺、等比放大裁切（`cover`）。安全区取**中间 750×1400**，上下各 112px 可裁。

### 2.3 `panel_card.png` — 白圆角卡片（九宫格）

**这一版恢复用图**。我上一版主张改 CSS，前提是"两端各写各的"；程序实际是浏览器 + 微信共用同一套 Canvas，那么**一张九宫格图比两处手写圆角裁剪更稳**。

| 项 | 值 | 说明 |
|---|---|---|
| 画布 | **600×800**（透明 PNG，5.6 KB） | 大于任何实际用到的尺寸，所以对角片永不放大 |
| 圆角 | **32**（绝对像素，不按宽度缩放） | 600 宽下的值；设计稿 750 坐标系直接用 32 |
| 边线 | **1px `#E3E9F2`**，沿圆角内侧 | 整圈都在 64px 切片内，拉伸不会变粗变细 |
| 顶部暖光 | **0 → 64px，`#FFFBF2` → `#FFFFFF`** | 64px 正落在上切片边界，拉伸后仍只在顶部 |
| 投影 | **图内无投影** | `0 4px 16px rgba(44,58,75,.10)` 由外层加 |
| **九宫格切片** | **`slice = 64, 64, 64, 64`** | 四角装饰全部落在 64px 半径内；中间 **472×672 纯白**，可任意拉伸 |

**程序接入（Canvas 2D / 微信小游戏）**

```js
ctx.drawImage9(img, dx, dy, dw, dh, 64, 64, 64, 64);   // 或自写九宫格
// 投影用 ctx.shadowColor='rgba(44,58,75,.10)'; shadowBlur=16; shadowOffsetY=4;
```

微信小游戏没有内置 `drawImage9`，按下表切九块 `drawImage(src, sx,sy,sw,sh, dx,dy,dw,dh)`：

| 块 | sx, sy, sw, sh | dx, dy, dw, dh |
|---|---|---|
| 四角 | 源四角各取 64×64 | 目标四角各 64×64，**不缩放** |
| 上 / 下边 | `(64,0,472,64)` / `(64,736,472,64)` | `(64,0,dw-128,64)` / `(64,dh-64,dw-128,64)` |
| 左 / 右边 | `(0,64,64,672)` / `(536,64,64,672)` | `(0,64,64,dh-128)` / `(dw-64,64,64,dh-128)` |
| 中心 | `(64,64,472,672)` | `(64,64,dw-128,dh-128)` |

**目标尺寸限制**：`dw ≥ 128, dh ≥ 128`（否则角片会互相压住）。本版实际用到：结算面板 590×700 ✅、设置面板约 590×620 ✅、关卡格约 300×300 ✅。

**关卡格「锁定」态**：卡片上叠一层 `rgba(44,58,75,.10)` + 图标换 `#C3CDD9`，**不要**换深色卡片（会破坏明亮基调）。

### 2.4 主界面装饰：四块板拼的小房子（不定稿素材，程序画）

主理人 2026-11-18 定：主界面**标题与主按钮之间**那片空白补一个视觉锚点，**用玩法本身的板件拼**，零成本。

- **允许这种装饰性拼板出现**。它是纯装饰 —— 不参与判定、不可点、点击穿透、不显示描边文字。
- 摆法由我给的 `deco_house()` 定（见 `tools/gen_style_preview.py`）：**D 当屋顶 → A 当身 → C+B 当基座**，整体缩到 **162×162**，居中在 **x=375，顶边 y=730**（副标题 612 → 按钮 1010 之间，上下各留 118，视觉居中）。
- **`globalAlpha = 0.55`**，一次性整体半透明（不要逐块调不同透明度）。
- 观感目标：**一眼看出是房子，但不抢标题**。所以不允许加投影文字、不允许加描边。
- 程序用 4 次 `fillPath` + 1 次 `globalAlpha` 即可，**不需要任何图片**。
- **正式关卡里不许出现这种"非解"的摆法**当提示（会误导玩家），它只出现在 P1。

> **为什么刻意保持松散、不排紧（这是主理人明确的决定，别"优化"掉）**
> 如果排成严丝合缝的房子，玩家会把它当成**标准答案**去临摹。而四巧板是**多解**的，一旦心里有了"标准答案"，玩家就不再探索，卡住时只会怀疑自己"摆得不像"。
> **露出一点缺口恰恰是对的**：它传达的是"这几块能拼出形状"，而不是"照这个拼"。这是引导，不是答案。
> 所以：**不排紧、不降低 D 燕尾凹口的可见度、不补满基座右侧那 0.5u 的空档。**

### 4.2 板件四色（7.1，**不要黑描边**）

## 5. 板件视觉校准（程序实现基准）

按顺序绘制，**4 层，不要合并**：

### 第 1 层 · 柔投影
```
offsetY = 2, blur = 6, color = rgba(44,58,75,0.14)
```
Canvas：`ctx.shadowColor/ shadowBlur=6 / shadowOffsetY=2`，填充后立即清 shadow。
⚠️ 投影随旋转，但**不能随「翻转」镜像**（否则光照方向会翻到背面）。

### 第 2 层 · 纯色填充
直接用 §4.2 填充色。**无渐变、无木纹、无噪点** —— 6.5 硬性禁止：板件加纹理会让形状边界变糊，直接损害玩法可读性。

### 第 3 层 · 顶部内高光（"糖果厚度感"的来源）
```
1.5px, rgba(255,255,255,0.25)
只画「朝上的边」，不是整圈描边
```
- 判定：每条边求外法线，法线 `y < -0.15` 的边才画。
- 省事近似：`原多边形 − 上移 1.5px 后的多边形` 取差集，得到的月牙带即顶边高光（效果图用的是这个做法，视觉等价）。
- ⚠️ 翻转后要按**新形状**的朝上边重算，不能直接镜像。

### 第 4 层 · 描边
```
2px，颜色见 §4.2，strokeAlign = INSIDE
```
- **必须内侧**：画外侧会让 A 板外扩 2px，托盘里 4 块板缩放后边界不一致，吸附顶点对位看起来会差 2px。
- **禁止 `#000`**。

### 交互态（只给视觉，时长引用白动远的动效规格表）

| 状态 | 视觉变化 |
|---|---|
| 吸附命中 | 板外扩 **2px 白色 60%** 高亮环（外扩，不改填充；**不用发光/glow**） |
| 吸附范围内拖动 | 同一圈环 alpha **0.25 ↔ 0.60** 呼吸 |
| 抓取 | 上浮 4px + 缩放 1.04（只位移缩放，不变色） |
| 重叠提示 | 重叠区叠 **2px `#E5484D`** 红轮廓闪 2 次（红只作"错误"语义，不在板件配色体系内） |
| 禁用 | 板件无禁用态（禁用的是按钮，不是板） |

### 尺寸与标记
- **托盘内**：等比缩放进 **168×168** 槽位，内边距 **12px** → 有效 **144×144**（7.1）。
- **自适应下限**：B 板在 1000 坐标系下约 50×50，映射到 **702** 宽拼图区约 **35×35 设计像素**，2px 描边占 5.7% 会吃掉填充 → **外接框 < 40px 时描边降到 1.5px**。
- **D 板翻转标记**：凹口内侧 45° 虚线，长 14 / 宽 2 / `rgba(255,255,255,0.8)`，画在**板本地坐标系**（随旋转转、随翻转变）。

## 7. SVG 图标集（9 枚，合计 3.1 KB）

| 文件 | 用途 | 尺寸 |
|---|---|---|
| `back.svg` | 返回 | 44 视觉 / **88×88 热区** |
| `rotate-left.svg` | 逆时针 45° | 44 / 120×100 |
| `rotate-right.svg` | 顺时针 45° | 44 / 120×100 |
| `flip.svg` | 水平翻转 | 44 / 120×100 |
| `hint.svg` | 提示灯泡 | 44 / 120×100 |
| `reset.svg` | 重来 | 44 / 120×100 |
| `gear.svg` | 设置 | 48 / **88×88** |
| `star-on.svg` / `star-off.svg` | 星级点亮 / 未点亮 | 32~56 |

**统一规格**
```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 40 40" fill="none"
     stroke="currentColor" stroke-width="2.5"
     stroke-linecap="round" stroke-linejoin="round" aria-hidden="true">
```
- **无写死宽高**，只有 `viewBox` → 任意尺寸自适应。
- 单色 `currentColor`；禁用态只换颜色 `#C3CDD9`，**不需要第二套文件**。

**接入方式（重要）**
1. **推荐内联** —— `currentColor` 才生效、零请求。
2. `<img src>` 引入 → `currentColor` 失效（img 是独立文档），需要预先写死颜色。**要改色就别用 img**。
3. Canvas 侧：`Image` 加载 `data:image/svg+xml;utf8,` 并把 `currentColor` 替换成目标色字符串；或按 `art-src/tools/gen_icons.py` 里的几何参数用 Canvas path 重画。

**设计说明**
- `rotate-left` / `rotate-right` 是**严格镜像**（弧 270°、开口朝上、箭头在顶部指切向）。**不要用同一个图标加水平翻转**——会得到错误的旋转语义。
- `reset` 是"近闭合整圈 + 右下箭头"，与旋转系列的"大开口圆弧"刻意区分。工具栏 5 个图标相邻，这是唯一能让人一眼分清"旋转"和"重来"的办法。
- `gear` 是 8 枚梯形齿 + 中心孔的真实齿轮轮廓（不是"圆 + 放射线"，那在 24px 下像太阳）。
- `star-on` / `star-off` 用**同一路径**（实心/空心），逐颗点亮时外轮廓不跳。
