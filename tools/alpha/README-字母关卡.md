# 字母关卡（七巧板）方案与现状

## 1. 结论先说
参考图（26 个七巧板字母）是**插画**，不是严格的七巧板施工图：
- 逐块量出的面积偏离标准值最多 ±12%（标准为 4 / 2 / 1）
- 笔画宽度约 √2u（≈1.41u），而七巧板所有顶点落在整数格上，不可能出现宽度 √2 的笔画

因此「按像素逐块反解」不可能得到 7 块严丝合缝的解（实测第 7 块永远放不下）。
现在的做法是：**把参考轮廓当设计意图，用精确覆盖求解器重新构造严格解**，允许剪影与参考有 5%~20% 的面积偏差。

## 2. 管线（tools/alpha/）
| 文件 | 作用 |
|---|---|
| `pieces_alpha.py` | 从字母图按颜色分离 7 块板、用板型模板拟合板型与朝向 |
| `sil.py` | 取字母外轮廓与内孔，转到「旋转 -45°」的 S 帧（板型顶点在此为整数） |
| `cover.py` | **精确覆盖求解器**：每个单位方格切成 4 个小三角（无损离散），7 块板必须恰好占 64 个小三角 = 面积 16 |
| `letter.py` | 组装流程：轮廓 → 容器 → 求解 → 排序（偏差 / 斜边数 / 该不该有内孔） |
| `final.py` | 输出对比图 + `solutions.json`（outline 为 u 单位多边形，pieces 为 7 块板的顶点） |
| `verify.js` | **用游戏自己的 `js/judge.js` 验收**：coverage / overflow / 逐对重叠阈值 |

## 3. 已完成的工程改动
`js/judge.js` 的 `setTarget(outline, holes)` 增加了内孔支持（A、P 这类字母必须有内孔）。
新增 `rasterize` 的 `'hole'` 模式（把目标格数减掉）。旧调用 `setTarget(outline)` 行为不变。

## 4. 验收结果（node tools/alpha/verify.js）
15 个解出且偏差达标的字母中，**12 个通过游戏判定**（coverage ≥0.99、overflow ≤1%、无真重叠）：
E / F / H / I / K / L / M / N / S / W / X / Y。
未通过：A、P（各 1~2 处被判为重叠，实为拼缝压在判定栅格中心）、V。

## 5. 可辨识度（人工判读）
清楚：**E、F、L、M、N、S、W、Y**（8 个）
勉强：I、H、K、X（剪影有斜切缺口，读起来不像）
未解出/质量不足：B、C、D、G、J、O、Q、R、T、U、Z

## 6. 后续三条路
1. **手工设计**：在整数格上手工摆这 26 个字母，形状会有意偏离参考图，但一定严格、一定好看（每个字母 5~10 轮迭代）
2. **只上做得好的**：把 8~12 个字母作为「字母章节」，其余关卡仍用几何图形
3. **换题材**：用经典七巧板图形（房子、船、猫、箭头、T 字、十字等）——这些是有公开解法的严格图形
