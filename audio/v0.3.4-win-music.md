# v0.3.4 A4b · 欢快通关音乐（余听声 / 音效线）

版本：v0.3.4 ｜ 交付：2026-11-19 ｜ 触发点：`core.js win()` → `env.audio.play('sfx_win')`（每关拼成功都播）

> **修订 r2**：采纳动画线 A4a 关键帧，把顶点重音前移到 242ms 与主花绽放峰值同帧；上行/和弦 offset 相应收紧，总时长 0.82s。**以本版 §2.2 代码为准（覆盖初版代码）。**

---

## 0. 结论先行

**采用方案：Web Audio 合成（synth），不生成音频文件。**

理由：
1. **能达到"欢快音乐"效果**：一段"快速大调上行琶音 + 顶点重音 + 顶点持续大三和弦"的短号角式进行，用现有 `tone()` 的 triangle/sine 波形 + 指数包络完全能做出明亮、有成就感的庆祝感，比当前温润三音明显更"叮咚庆祝"。顶点重音与鲜花绽放峰值同帧（§1.5），进一步放大成就感。
2. **自包含**：零新增文件、包体不变、断网/file:// 双击都可播，符合规格 §2.2「不新增外部图片/网络依赖」与 V8 自包含验收。
3. **双端天然一致**：同一段函数原样贴进两端 synth，无需同步 assets。
4. **省预算**：合成零积分消耗，10 分预算本版不动用，留给后续版本 BGM。

> ⚠️ **必须配套的接入改动（关键，见 §3）**：现有 `playSfx()` 的分发优先级是 **文件 buffer → 元素池 → synth（最后兜底）**。因为 `sfx_win.mp3` 存在且能加载，若程序线只替换 synth 函数而**不做 §3 的强制转接，新旋律根本不会被听到**。这是本交付最容易踩的坑，请程序线务必执行 §3。

## 1. 音乐设计说明

### 1.1 情绪基调
"成功拼出图案"的即时庆祝：明亮、轻快、有收束感（成就感来自顶点重音 + 大三和弦的稳定落点）。定位为**短提示音乐（ sting / fanfare ）**，不是循环 BGM——播完即止，约 0.82 秒。旋律顶点重音与动画线主花绽放峰值（t≈242ms）同帧，见 §1.5 音画同步对齐。

### 1.2 配器思路（纯 Web Audio）
- **主旋律**：triangle 波（奇次谐波按 1/n² 衰减，比 sine 亮、比 square 柔），做 C 大调五声音阶的快速上行琶音 `C5–E5–G5–C6`，制造"节节升高 = 达成"的推进感。
- **顶点重音**：第 4 音 C6 用 triangle、gain 0.16（高于上行前三音的 0.13–0.14），是全曲最响、最高的点，与鲜花绽放峰值同帧落下，形成"叮！成了"的成就感重音。
- **落点和弦**：三音 `C6/E6/G6`（C 大三和弦原位高把位）用 sine 波、错开 30ms 依次进入，形成"叮——亮起"的微光感，同时给稳定的终止感 = 成就感。高频音刻意压低 gain，避免手机小喇叭上的刺耳；dur 拉长到 0.46–0.50s，让结算面板（660ms）出现时音乐已进入尾音段。
- **包络**：沿用现有 `tone()` 的 6ms 快起 + 指数衰减（类钢琴拨奏），上行音有一点重叠形成连奏，不断续、不机械。

### 1.3 与现有音频的关系
- **BGM**：本 sting 落在 `winShrink(260)+winDelay(400)=660ms` 的鲜花窗口内起音，延续到结算面板出现之后；此时 BGM 已从 0.30 duck 到 0.18（`core.js:892`），正好让通关旋律露出来。不与 BGM 抢频：BGM 是常态铺底，sting 是 1 秒内的高层点缀。
- **其它 SFX**：`win()` 里 `state.running=false`，之后 tap/pick/snap 不再触发， sting 独占场地，不会叠音。
- **不循环**：一次性播放，不做 loop。

### 1.4 时长与结构
| 阶段 | 时间窗 | 内容 |
|---|---|---|
| 上行琶音 | 0.000–0.462s | C5 → E5 → G5 → C6，四音爬升（ triangle ） |
| ★顶点重音 | 0.242s | C6 gain 0.16（高于上行音）与主花绽放峰值同帧 |
| 收束和弦 | 0.300–0.820s | C6/E6/G6 错峰进入并延长衰减（ sine ），结算面板出现时已进入尾音 |

总时长 **≈0.82s**（规格建议 0.8~1.5s ✔）。

### 1.5 音画同步对齐（与动画线 A4a 共用 `state.win.t` 基准）
动画线给出鲜花关键帧，本 sting 用「相对 win 的毫秒 offset」与之对齐，两端 synth 与 Canvas 天然同基准：

| 动画关键帧（白动远 A4a） | 本 sting 对应 | 是否对齐 |
|---|---|---|
| t=0 鲜花起苞（与 sfx_win 同起点） | C5 起音 offset 0.000 | ✔ 同帧 |
| 120/165/210/255/300/345ms 六朵卫星花依次弹开 | E5≈82ms、G5≈162ms、C6≈242ms、和弦根≈300ms、E6≈330ms | ✔ 音头落在卫星花区间（非逐朵硬对，保持上行舒展、不急促） |
| t≈242ms（230–260）主花 scale 峰值 ≈1.14 | C6 triangle gain 0.16 顶点重音 offset 0.242 | ✔ **精确同帧，成就感峰值** |
| t=660ms 结算面板出现、鲜花淡出 | 和弦处于衰减尾音（300ms 起、820ms 结束），660ms 期间无新音头 | ✔ 不抢星级逐颗亮（starStep=120ms） |

> 采纳动画线建议：把初版顶点音从 300ms 前移到 242ms 并加大 gain 做重音，使"音乐最高音 + 最响点"与主花视觉峰值同帧——这是强化"成就感"的关键音画同步点。卫星花未逐朵硬对 6 个音头（45ms 间隔的琶音会显得急促、反而削弱庆祝感），改为让上行音头落在弹开区间内，兼顾同步与听感。

### 2.1 音符参数表（数据来源，便于调参/复核）

| 1 | C5 | 523.25 | triangle | 0.12 | 0.13 | 0.000 | t=0 起苞 |
| 2 | E5 | 659.25 | triangle | 0.12 | 0.13 | 0.082 | 卫星花区 |
| 3 | G5 | 783.99 | triangle | 0.13 | 0.14 | 0.162 | 卫星花②≈165ms |
| 4 | C6 | 1046.50 | triangle | 0.22 | 0.16 | 0.242 | ★主花峰值≈242ms 重音 |
| 5 | C6 | 1046.50 | sine | 0.50 | 0.10 | 0.300 | 和弦根 / 卫星花⑤≈300ms |
| 6 | E6 | 1318.51 | sine | 0.48 | 0.09 | 0.330 | 和弦三音 |

峰值估算：顶点重音点（242ms）约 0.17；和弦段（360ms 附近）约 0.17–0.20；全程 ≤0.25，远低于削波；手机外放不刺耳。和弦 dur 拉长到 0.46–0.50s 是为了让 660ms 结算面板出现时音乐已在尾音段。

### 2.2 代码片段（两端完全一致，原样替换现有 `sfx_win`）

复用现有 `tone(freq, dur, type, gain, delay, slideTo)`，无需新增任何 helper。预览端 `preview/js/game.js:107` 与微信端 `miniprogram/game.js:129`：

```js
  sfx_win: function () {
    // v0.3.4 A4b：欢快通关 sting — C 大调上行琶音 + 顶点重音 + 收束和弦（约 0.82s）
    // offset 与动画线鲜花关键帧共用 state.win.t 基准：242ms 顶点重音对齐主花绽放峰值
    // triangle 上行（明亮），C6 gain 0.16 做重音；sine 收束和弦高频压低 gain 防刺耳
    tone(523.25, 0.12, 'triangle', 0.13, 0.000);  // C5 — t=0 起苞
    tone(659.25, 0.12, 'triangle', 0.13, 0.082);  // E5 — 卫星花区
    tone(783.99, 0.13, 'triangle', 0.14, 0.162);  // G5 — 卫星花②
    tone(1046.50, 0.22, 'triangle', 0.16, 0.242); // C6 — ★顶点重音，对齐主花峰值 242ms
    tone(1046.50, 0.50, 'sine', 0.10, 0.300);     // C6 和弦根
    tone(1318.51, 0.48, 'sine', 0.09, 0.330);     // E6 和弦三音
    tone(1567.98, 0.46, 'sine', 0.06, 0.360);     // G6 和弦冠（压低高频）
  },
```

**替换还是新增？** —— **直接替换**现有 `sfx_win` 函数体（触发点不变，`core.js` 里 `play('sfx_win')` 一个字都不用改）。不新增 `sfx_win_joy`：新增需要程序线改调用点，徒增改动面；替换即可，且旧文件 `sfx_win.mp3` 保留不动（见 §3 说明为何它不会干扰）。这样也满足动画线"别和 sfx_win 叠成两个叮"——新旋律直接替换旧音，不会双响。

> 两端函数名、`tone` 签名、`masterGain=1` 均一致，代码可直接同文贴入；符合硬约束 §2.3「两端 synth 逻辑一致」。

### 2.3 可选微调（不改主方案，供程序线试听后自选）
- **想更"跳跃"**：把上行四音（前 4 个 `tone`）的 offset 整体等比缩到 0.9 倍——注意顶点重音那句要同步前移，仍与主花峰值同帧（动画线峰值区间 230–260ms，前移至 ~218ms 会略早，慎改）。
- **想更"厚"**：在 0.000 处加一句 `tone(261.63, 0.10, 'sine', 0.07, 0.000);`（C4 低音垫，增加"落地"重量）——但与 BGM 低频略有交叠，默认不加。
- **想更"闪"**：在 0.620 处加 `tone(2093.0, 0.14, 'sine', 0.035, 0.620);`（C7 极轻尾音），手机外放几乎听不见，仅在耳机下增色，默认不加；此处已在结算面板出现后，不属新强拍。

## 3. 程序线接入说明（⚠️ 必读，否则听不到新旋律）

### 3.1 问题：synth 是最后兜底，文件会抢先播
两端 `playSfx(name)` 的分发顺序是：

```
buf[name] && AC        → 解码后的音频 buffer（sfx_win.mp3）   ← 先命中
elementMode            → <audio>/InnerAudioContext 元素池     ← 或命中
synth[name]()          → Web Audio 合成                       ← 仅上面都失败才走
```

现状 `config.js AUDIO.files.sfx_win = 'sfx_win.mp3'` 存在且能加载，所以 99% 情况下**走的是 mp3，synth 不会执行**。只替换 synth 函数 = 玩家听到的还是旧三音。

### 3.2 推荐改法（方案 A，最小改动，两端各加一行）
在两端 `playSfx()` 内、`enabled.sfx` 检查之后、分发逻辑之前，插入：

```js
  if (name === 'sfx_win') { if (synth.sfx_win) synth.sfx_win(); return; }
```

等价的完整位置参考（预览端 `preview/js/game.js:213`、微信端 `miniprogram/game.js:237`）：

```js
function playSfx(name) {
  if (!enabled.sfx) return;
  if (name === 'sfx_win') { if (synth.sfx_win) synth.sfx_win(); return; } // ★ v0.3.4 A4b 强制走合成
  // ...原有 snapVoices / tapGuard 逻辑...
```

效果：`sfx_win` 永远走新合成旋律；其余音效分发路径完全不变。`sfx_win.mp3` 成为未使用的遗留资源，**不必删除**（删了反而要动 assets，无收益）。零 config 改动、零 assets 改动、包体不变。

### 3.3 备选改法（方案 B，不推荐）
从 `js/config.js` 的 `AUDIO.files` 里删掉 `sfx_win: 'sfx_win.mp3'`，并跑 `node tools/sync.js` 三端同步。这样 synth 自动成为 sfx_win 的唯一路径。缺点：动了 config.js（要过三端 md5 一致验收），mp3 文件仍留在 assets 里成死资源。**除非程序线有更强的洁癖诉求，否则用方案 A。**

### 3.4 一句话给程序线
> 把两端 `synth.sfx_win` 换成 §2.2 的 r2 代码，再在两端 `playSfx()` 开头加 §3.2 那一行强制转接（`sfx_win` 走 synth、`return`），其余照旧；不用动 config、不用动 assets、不用动 core.js。

### 3.5 自动播放 / 手势解锁
现有 `audio.play()` 已先调 `resumeAudio()`（`preview/js/game.js:259`、`miniprogram/game.js` 对应处），且通关必然发生在玩家多次拖拽（首次手势）之后，AudioContext 已解锁，无需额外处理。

## 4. 混音基准

| 项 | 值 | 说明 |
|---|---|---|
| 主输出 | `masterGain = 1.0` | 现有值，未改 |
| 本 sting 单音 gain | 0.06 – 0.16 | 见 §2.1；为**绝对幅度**（合成路径直连 masterGain）；顶点重音 0.16 是全曲最响点 |
| 本 sting 峰值 | ≤ 0.25 | 顶点与和弦段均低于此值，无削波风险 |
| BGM 常态 / duck | 0.30 / 0.18 | 现有值，未改；结算面板出现时自动让位 |
| 相对层级 | sting ≫ duck 后 BGM | 通关瞬间 sting 是绝对主角，面板出现后 BGM 退回铺底 |
| `config.js sfxGain.sfx_win` | 1.00（保持） | **注意**：合成路径不读 sfxGain（该值只作用于文件/元素路径），无需调整；也不受 ±5% 随机变调影响——对旋律是好事，音准稳定 |

建议试听时把手机外放音量调到中档：上行四音应清晰可辨、不闷；顶点重音与主花绽放同时落下、明亮但不扎耳；结算面板出现时和弦已是轻柔尾音。若个别机型觉得偏响，整体等比下调 §2.2 里所有 gain 的 10% 即可，勿单独压高频音以外的值。

## 6. 缺失说明 / 本版未做

- **不做 BGM 改动**（规格 A4b 边界）：主界面/游戏中/结算 BGM 一律不动。
- **不做其它 SFX**：tap/pick/snap 维持现状。
- **不做星级逐颗亮音效**：该时刻（660ms 起、starStep=120ms）本 sting 已进尾音，不新增音效去抢；若程序线另有星级音，与本 sting 尾音层级不冲突（尾音 gain≤0.05）。
- **不做失败/全通关专属音乐**：本 sting 每关成功都播（含全通关），规格未要求区分。
- **不生成 wav/mp3**：合成已能满足欢快诉求，且更符合自包含/包体/双端一致；若真机试听后主理人仍判定"不够像音乐"，再按备选方案生成文件（预计需 10 分预算全额，两端 assets + config 同步），当前不动用预算。
- **不碰源码**：本交付只含规格与代码片段，未改任何 `js/`、`core.js`、`levels.js`。
