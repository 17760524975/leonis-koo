# v0.42 邀请面板：奖励图标化 + 每行进度条 + 可滑动

## 改了什么

用户拿着对标图提了三条：

1. **奖励全部换成图标**，不要「30 巧币 + 1 查找道具」这种文字；
2. **每行中间加一条进度条**，能直接看到「已邀请 2 / 需要 3」；
3. **一页放不下要能滑动**，别把卡片撑到看不见底。

三条都做了，版式也按对标图重排：金色行标 + 图标区 + 进度条 + 右侧按钮。

```
┌ 累计邀请 3 人进入游戏 ────────────────────┐   金色行标（浅色实金 / 深色半透明金）
│  [⚡×20] [💎×1]   ▓▓▓▓▓░░░ 3/4   [ 邀请 ] │   图标 + 进度条 + 蓝色分享按钮
└──────────────────────────────────────────┘
```

## 一、奖励 → 图标

`tierRewards(t)` 把一档奖励拆成图标序列，顺序固定为
**巧币 → 体力 → 查找道具 → 板件 → 背景**，每档最多两个，图标下方写 `×数量`。

| 档位 | 图标 | 档位 | 图标 |
|---|---|---|---|
| 1 人 | 🪙×30 💡×1 | 5 人 | ⚡×10 🎨马卡龙×1 |
| 2 人 | ⚡×20 🎨霓虹×1 | 6 人 | 💡×1 🪙×50 |
| 3 人 | 🎨水晶×1 🌸泡泡×1 | 7 人 | 💡×1 🌸花瓣×1 |
| 4 人 | ⚡×10 💡×1 | 8 人 | 🎨荧光×1 💡×1 |

巧币 / 体力 / 查找道具直接用游戏里那套徽章图标（`drawIcon`），**板件和背景没有现成图标**，
所以单独画了一个「小样」（`drawRewardIcon` / `drawBgSwatch`）：

- **板件** = 圆底 + 该质感的小三角（复用皮肤面板的 `drawPreviewPiece`，颜色用固定色板，
  霓虹紫、水晶蓝、马卡龙粉、荧光绿各不相同）；
- **背景** = 圆底 + 该特效的底色和招牌粒子（泡泡画四个彩色气泡、花瓣画四片粉色花瓣、
  星点/雨雪/萤火用主题色点）。

为什么不用「把皮肤面板那张 120px 预览缩到 42px」：缩完就糊成一团，认不出是哪个。
单独画的小样在 42px 下还能看出是气泡还是花瓣。

## 二、每行中间的进度条

`填充比例 = min(已邀请 / 需要, 1)`，条形正中间写 `已/需`（如 `2/3`）。
达标整条变金色、文字转深棕（`COL.btnText`），未达标只填一段、文字用次要色 ——
深浅两种皮肤都验过对比度（金底配深字，不是白字）。

进度条宽 190、高 30，横向正好落在行正中，左边图标区、右边按钮区互不挤。

## 三、可滑动

8 档 × 行距 130 = 1028px，而视口（卡片高 − 顶部 162 − 底部 128）在 750×1624 上只有 890px，
**所以一定溢出，滑动是主交互而不是兜底**。小屏（可用高度不够）时卡片高自动降到 860，
视口更矮，滑得更长，逻辑不变。

- `state.inviteScroll` / `inviteScrollMax`：当前偏移与上限，越界一律夹在 `[0, max]`；
- 视口用 `rr()` 圆角裁剪，完全在视口外的行**不画也不登记热区**（省绘制、免幽灵按钮）；
- 右侧一条 5px 滚动条（金拇指），只在装不下时出现，顺带提示「这里能滑」；
- 每次打开面板 `inviteScroll = 0`，从第 1 档看起。

### 手势：拖与点不打架

`onDown` 在列表视口内起一个拖动会话（`state.scrollDrag`），`onMove` 位移 > 10px 才
**升级为滑动**并立刻取消待触发的按钮；`onUp` 时若拖动过就不算点击。
所以「手指按在『邀请』按钮上往上滑」只会滚动，不会稀里糊涂发一条分享。

按钮热区用 `addListHit` 登记：只覆盖真正露在视口里的那一段（高度 < 24px 直接不登记）。
