## 一、为什么要改

v0.23 定下的规矩是「首通给一次，1★2 / 2★3 / 3★5，重复通关 0」。这条规矩解决了当时的刷币漏洞（第 1 关 30 秒一局稳拿 30 巧币），但同时把「练到三星」这件事的回报也一起砍掉了：

- 玩家 1★ 过关之后，再回来打 2★ / 3★ **一分钱都拿不到**；
- 三星只影响星星总数（榜单展示），不影响任何收益；
- 结果就是老关卡没人重玩，内容消耗完就流失。

v0.40 换成「**总额制 + 补差价**」：每关每个星级都有一个应得总额，结算时补「应得总额 − 这一关已经发过的」差额。

## 二、数值表

| 星级 | 应得总额 `starReward` | 相对于上一档的差价 |
|---|---|---|
| ★☆☆ | 21 | —（首通 21） |
| ★★☆ | 32 | **+11**（1★ 升 2★） |
| ★★★ | 53 | **+21**（2★ 升 3★） |

跨级的情况直接补齐到目标星级总额：

| 场景 | 进账 |
|---|---|
| 首通 1★ | +21 |
| 1★ → 2★ | +11 |
| 2★ → 3★ | +21 |
| 1★ 直接打回 3★ | **+32**（= 11 + 21） |
| 同星级重打（1★→1★、2★→2★） | +0 |
| 已经 3★ 再打（哪怕这局只有 1★） | +0 |

> ⚠️ 用户举例里写「1 星玩到 3 星给 31 巧币」，但按 21+11+21 的逐级口径，跨级应当是 **32**。取 32 的理由：如果跨级给 31，玩家会发现「先升 2★ 再升 3★」比「一次跳到 3★」多拿 1 巧币 —— 规则自己和自己打架。所以这里按「总额必须自洽」取 32，逐级差价 11 / 21 与用户给的数字完全一致。

## 三、不会变成刷币漏洞

这是本次设计最要紧的一条：**每关的总额恒定封顶 53**。

存档里新增 `starPaid[k]`（这一关已经发放的累计额），结算时：

```
本局进账 = starReward[该关历史最高星级 - 1] - starPaid[关卡号]
```

- 同一关无论重打多少次，累计只可能拿到 53（首通 21 + 补差 11 + 补差 21）；
- 打回低星级不会倒扣，也不会重发；
- 存档里只记「最高星级」和「已发额」，两个数都是单调的，没有可以来回刷的状态。

## 四、看视频 ×5

`grantWinAdMul()` 的判定从 `result.first`（必须首通）放宽到 `result.gain > 0`（这一局有进账）：

- 首通 3★：+53 → 看视频后 +265；
- 升星补差 +21 → 看视频后 +105；
- 没有进账的局（同星级重打）：不给 ×5 入口。

一个刻意的细节：**翻倍的加成不写进 `starPaid`**。
比如 1★ 拿 21、看视频 +84，账上仍记 21；之后升到 2★ 依旧补 11（翻倍再 +44），升到 3★ 依旧补 21。
如果把这 84 也算进「已发额」，玩家一次翻倍之后，后面两次升星就都成了 0 奖励 —— 明明是同一关的进度，却因为「提前看了广告」被惩罚。

## 五、老存档怎么迁移

v0.39 及以前的存档只有 `starOf`（星级），没有金额账。加载时按 **旧口径 2 / 3 / 5** 补记：

```js
starPaid[k] = [2, 3, 5][starOf[k] - 1]
```

三种方案里只有这一种是合理的：

| 迁移写法 | 后果 |
|---|---|
| 记 0 | 所有老关重发一遍，一进游戏凭空多几百巧币 |
| 记新总额 21/32/53 | 老玩家的 1★/2★ 关升星一分钱都拿不到，改了等于没改 |
| **记旧值 2/3/5** | 老玩家升星时把历史差额一并补上（1★ 老关升 2★ 给 30），一次性补偿、总额仍在 53 以内 |

云同步的 `mergeSave()` 对 `starPaid` 取 `max`：两台设备各升一次星时不会重复发钱。

## 六、界面上怎么让人看见

1. **关卡列表**：已通关但没满 3 星的卡片，关号右边挂一个金色小标签 `↑11` / `↑21`，写的就是「再升一星能补多少」。满 3 星后标签消失。没有这个提示，玩家根本不知道重玩老关有进账。
2. **结算页奖励条**：四种文案
   - 首通：`首通奖励 +21 巧币 · 本关视频 3/3`
   - 升星：`升到 ★★★ · 补差 +21 巧币 · 本关视频 2/3`
   - 已翻倍：`升到 ★★★ · 补差 +105 巧币 · 已翻 5 倍`
   - 无进账：`已通过 · 星级未提升，无奖励`
   条底的金色强调也从「是不是首通」改成「有没有进账」—— 升星补差是真的拿到钱，用灰条会让人以为白打一局。

## 七、背景「泡泡漂浮 / 萤火之森」各 100 巧币

`config.BG_FX` 里加 `price: 100`，走的是 v0.39 已有的那套付费流程（价签 → 确认页 → 扣款 → 全局解锁表 `tangram_shop_v1`），代码零改动，只是配置多两行。

现在付费背景共 **5 套**：

| 背景 | 价格 |
|---|---|
| 星夜流萤 | 150 |
| 花瓣飘落 | 150 |
| 初雪纷飞 | 150 |
| **泡泡漂浮** | **100** |
| **萤火之森** | **100** |

顺手修了一个预览问题：泡泡的预览缩略图原来是「白色描边圆圈画在白色卡片上」，等于没画。现在改成三色描边 + 淡填充 + 高光点，预览块铺淡蓝底（`#E4F2FB`），缩略图里能一眼认出是气泡。
