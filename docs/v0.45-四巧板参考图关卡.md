## 关键理论：合法剪影必然是 0.5 格点多边形

这一版最有价值的一步，是先证明「什么样的轮廓才可能被四块板拼出来」，再去拟合照片。

四块板的顶点（`js/levels.js` 顶部 `DATASET`）全部落在 **0.5 格点** `L = 0.5·Z²` 上。
摆到棋盘上时还有 45° 朝向：旋转矩阵 `R45` 把 `0.5·Z²` 映射到 `0.5·R45·Z²`。
这两张格点网在平面上**只共享原点** —— 因为 `R45` 会产生 √2 因子，而 √2 是无理数，
`a + b√2 = 0` 只有 `a = b = 0` 一个解。

推论：**两块奇偶性不同步的板（一块 0/90/180/270、一块 45°/135°）最多只能共用一个点，
拼不出有面积的连续区域。** 所以任何合法剪影要么整体在 `0.5·Z²` 系里，
要么整体在 `0.5·R45·Z²` 系里（转 45° 后等价）。换句话说：

> **所有可拼出来的图形，都是「整体 0°/45° 二选一 + 顶点落在 0.5 格点」的多边形。**

这条结论把「拟合照片」从连续优化降级成离散搜索：只要把剪影吸附到 0.5 格点，
吸附残差不为 0 的形状就永远拼不出来 —— 不用去试摆板。

## 三角网格精确覆盖

吸附到格点之后，摆板问题用**三角网格精确覆盖**来解，而不是整边贴整边的多边形枚举
（`enumerate.js` 那种做法做不到 T 型接缝，会漏掉大量合法解）：

- 每个 0.5×0.5 方格用两条对角线切成 **4 个三角形**，整关 96 个三角形（总面积 6u² = 96 × 1/16 u²）；
- 顶点全在格点 ⇒ 每块板要么整块盖住某些三角形、要么完全不碰，不存在「盖一半」；
- 于是「摆板」= 取三角形集合，「不重叠 + 铺满」= 整数集合的**精确覆盖**，可以纯 DFS 求解。

板型用 0.25u 整数编码（`tools/figs4/tri.js` 的 `BASE` / `AREA_TRI`），面积和正好 96：

```js
A:[[12,0],[0,0],[4,4],[12,4]]   B:[[0,4],[0,0],[4,4]]
C:[[0,0],[6,0],[2,4],[0,4]]     D:[[2,0],[2,4],[0,4],[4,8],[10,8]]
AREA_TRI = { A:40, B:8, C:16, D:32 }
```

三角形质心（0.25u）：`N=(X+1,Y+5/3)` `E=(X+5/3,Y+1)` `S=(X+1,Y+1/3)` `W=(X+1/3,Y+1)`。

## 求解链路（`tools/figs4/`）

| 步骤 | 脚本 | 做什么 |
| --- | --- | --- |
| 1 | `extract.py` | 照片 → 黑色轮廓线 → 闭合环 → 洪泛 → Moore 追踪 → 闭合 DP → 受方向约束的边拟合，输出 `poly.json`（描边贴合 0.993~0.996） |
| 2 | `snap.js` | 剪影 → 0.5 格点吸附：双轴尺度 + 相位 + 8 个预旋转，硬约束过滤（面积必须正好 6、边必须 45° 倍数、必须简单多边形） |
| 3 | `warp.js` | 书页仿射畸变校正：6 参数 `[a,b,c,d,tx,ty]` 上最小化 `Σdist²(v′, 格点) + 30·‖A−I‖²`，30000 次随机采样 + 坐标下降 |
| 4 | `tri.js` | 三角网格 + `exactCover()` |
| 5 | `fitTri.js` | f3/f5/f6 用的近似求解器：把剪影栅格化成三角形集合 T，对每块板取「≥90% 落在 T 内」的候选，**遍历 24 种放置顺序**穷举，最大化 `|并集 ∩ T|` |
| 6 | `finalize.js` | **轮廓一律由 4 块板的并集在格点系里重算**（不信任中间产物），再按形距对 8 个 45° 朝向取最优 |
| 7 | `export.js` | 转关卡对象：世界坐标 `p·130 + (500 − 65·round(2·cx), …)`，保证顶点落在 `500+65k` 点阵；反解 `{angle, flipped, x, y}` |

### 两类结果

- **f1 / f2 / f4 存在零误差精确解**：面积正好 6.000000、96 个三角形严丝合缝。
  f2 与 f4 的解与更早的 `out/solved.json` 记录完全一致 —— 两条独立路径互为交叉验证。
- **f3 / f5 / f6 的插画本身不是严格可拼的形状**。证据：
  - `snap.js` 16×16 偏移 × 4 预旋转穷举：f3 只有松弛解（吸附后面积 6.750）、f6 无任何解；
  - `warp.js` 仿射校正后：f3 / f6 无解；f5 吸出 108 个「面积正好 6」的格点解，**全部不可铺满**；
  - 结论：这三张图的尺寸不是半格倍数、窄凹口被描边吃掉了几像素。
  
  因此这三关取「**最接近的可拼形状**」：轮廓仍由 4 块板并集反推（**保证可解**），
  只是与插画有约 0.3u 的差异。形状还原度见上表（f3 0.797 / f5 0.858 / f6 0.636）。

### 踩过的两个坑

1. **`fitTri` 强制「每块必须贴住已放块」** → f2 的已知精确解被整个漏掉（形距 0.46）。
   改成全排列遍历 24 种顺序后回到 0.112。**这是本版最重要的算法 bug。**
2. **轮廓二次平移**：`best.ring` 已经是照片坐标系，`export.js` 又按 `ox,oy,pre` 变换了一次 ——
   轮廓平移两次、板件只平移一次，6 关判定覆盖率掉到 0.38 / 0.64 / 0.70。
   修法就是新建 `finalize.js`，轮廓**只在格点系里由板并集重算一次**。

## 章节分页的已知折衷（本轮未动）

分页实际按关数滑窗，不按 `chapter` 字段：`core.js:4359 chapterCount() = ceil(LEVELS.length / CHAP_PER)`、
`core.js:1781 state.lvPage = floor((um−1) / CHAP_PER)`，`CHAP_PER = 20`。
所以第二章从 10 关变 16 关之后，关卡页第 1 页显示「第 2 章 1-16 关」，
第 2 页覆盖 17–30 关（跨第二、三章）。`chapter` 字段本身是对的（10/16/10）。

要完美分页需要把 `chapPer` 改成 10 并给每关加章名/题名，会牵连 `core.js` 的分页逻辑
与存档 `unlockedMax` 的口径 —— 改动面和收益不成比例，本轮不动。
