> **给 AI 开发的说明**：本文是唯一口径。未列出的实现一律沿用现有代码，不要自行扩展。

> 本次发布号建议 **v0.65**；文件名沿用需求指定的 `v0.63-排行榜重设计规格.md`。

## 1. 页签定义

`config.RANK.tabs = ['全服榜', '好友榜', '本周榜']`，`unit = ['★', '★', '★']`。

| tab | 名称 | 数据源 | 排序键（依次） | 主数值 | 副信息 |
|---|---|---|---|---|---|
| 0 | 全服榜 | 云函数 `players` | `stars` ↓ → `cleared` ↓ → `updatedAt` ↑ | `★N` | `通关 M 关` |
| 1 | 好友榜 | 微信开放数据域 | `stars` ↓ → `cleared` ↓ → `streak` ↓ → 昵称 | `★N` | `通关 M 关` |
| 2 | 本周榜 | 云函数 `players` | `weekStars` ↓ → `streak` ↓ → `weekCleared` ↓ → `updatedAt` ↑ | `★N` | `连胜 S · 本周 M 关` |

- **连胜不再单独成榜**：`streak`（历史最高连胜）字段继续上报和保留，作为**本周榜的第 2 排序键 + 行内副信息**。删除原连胜榜页签与 `rank_t1` 点击分支，其余页签序号顺延：原好友榜 tab 2 → **1**，原本周榜 tab 3 → **2**。
- 星数排序优先于关数：星数含通关信息（3★ 必然已通关），区分空间是关数 3 倍，且接上 v0.60 三星门槛收紧的意图。
- 云数据库多字段 `orderBy` 若不支持，在云函数内取回前 N 条后二次排序；名次 `rank` 用复合条件 `count` 计算（主值更高，或主值相等但次值更高），不能只按单字段数。

## 2. 计分口径（玩家可自行核对）

- 每关最多 3★，沿用 v0.60 的 `STAR` 规则：`3★ = elapsed ≤ parTime × 0.8 且 steps ≤ parSteps`；用提示、复活不扣星（v0.19 口径）。
- **总星数 `stars`** = 两套题库各关**历史最高星数之和**，只升不降。
- **本周星数 `weekStars`** = 本周内每次通关按**本次星级**累加；同一关同一天只取最高星级计一次。重玩已 3★ 的关仍计 3★，所以满星老玩家和首通新玩家每周上限相同。
- 主榜饱和是可接受取舍（93 关 × 3 = 279★ 上限），回流竞争由本周榜承担。奖励仅虚拟荣誉（巧币/头像框/称号），禁止与现金、实物、付费挂钩。

| 场景 | `stars` | `weekStars` |
|---|---|---|
| 首次通关 | +实际星级 | +实际星级 |
| 重玩 1★→3★ | 只补 +2 | +3（按本次星级） |
| 重玩 3★→2★ | 不变 | +2 |
| 同日重复重玩同关 | 不变 | 只计当天最高一次 |
| 放弃 / 中途退出 | 不计 | 不计 |

## 3. 数据结构与云函数

### 3.1 `players` 字段

```
stars        number  总星数        ← 已有，直接复用
cleared      number  通关关数      ← 已有，直接复用
streak       number  历史最高连胜  ← 已有，保留（本周榜 tie-break）
weekStars    number  本周新增星数  ← 新增
weekCleared  number  本周通关关数  ← 新增
weekKey      string  YYYY-Www      ← 新增，UTC+8
starsV       number  口径版本 = 1  ← 新增
updatedAt    number
```

保留 `nick/avatar/src/auth/streakV`。**不要实现** `score/weekScore/scoreV/scoreRuleRev/scoreEvents/tier/difficulty`（旧草案已废弃）。

### 3.2 云函数 `miniprogram/cloudfunctions/player/index.js`

| action | 改动 |
|---|---|
| `sync` | 保留 `stars/cleared/streak` 的 `max` 合并；`stars ≤ 300`、`cleared ≤ 120`（现有 clamp 改为这两个值）。新增周星事件上报 `{uid, rev, stars: 本次星级, dayKey}`，按 `openid+uid+rev+dayKey` 在 `starEvents` 去重（同关卡版本当天只记最高星级一次），累加 `weekStars/weekCleared`。单条 `stars` 必须 1–3、单日周星增量 ≤ 60，超出拒绝。`weekKey` 不一致时先归零周字段。旧客户端无 `starsV` 时主榜照常合并、周星事件拒绝。 |
| `rank` | `tab` 接受 `0/1/2`（**不再有 3**）。`tab=0` 按 `stars`（次键 `cleared`）；`tab=1` 返回 `{ok:true,list:[],me:null,note:'friend'}`；`tab=2` 先做周切换再按 `weekStars`（次键 `streak`、`weekCleared`）。所有 tab 返回 `nextResetAt/weekKey`。 |

```
rank 返回：
{
  ok: true,
  list: [ { nick, avatar, v, v2, me } ],  // v=主排序值, v2=次排序值
  me:   { nick, avatar, v, v2, rank },
  totalPlayers: 123,
  nextResetAt: 1790000000000,             // 北京时间下周一 00:00
  weekKey: '2026-W48'
}
```

索引：`stars`、`cleared`、`weekStars` 各建降序索引（`starEvents` 建 `openid+uid+rev+dayKey` 唯一索引）。

### 3.3 周切换

- 云函数服务端生成 `weekKey`（UTC+8 自然周），客户端不算、不写 0。
- `tab=2` 请求时若玩家 `weekKey` 不同，先把 `weekStars/weekCleared` 归零并落库，再返回榜单；主榜字段不动。
- 客户端缓存 key 带 weekKey：`rankCache['2:' + weekKey]`。

### 3.4 好友 KV

- key `tangram_v2`，value `{cleared, stars, streak, weekStars, ts}`；旧 key `tangram` 读兼容 30 天，优先 v2。
- `friendrank.js` 的 `publish(stats)` 传 `stars/weekStars`。好友 KV 仅展示，不发放奖励。

## 6. 关卡扩充 / 改版长期约束

| 字段 | 规则 |
|---|---|
| `uid` | 稳定标识（`t4-001` / `t7-L026`），插队、改名、换章都不变 |
| `rev` | 轮廓 / 标准解 / 星级门槛 / `parTime` 变化才 +1 |
| `retired` | 下架标记，uid 永不复用 |

| 变更 | 处理 |
|---|---|
| 新增（含插队） | 新 uid，老玩家 `stars/cleared` 完全不变 |
| 修 bug 不改解 | rev 不变，历史星数保留 |
| 实质改版 | rev+1，旧星**不清零**；当天重玩新版可再计一次周星（去重 key 含 rev） |
| 下架 | 标 retired，历史星数保留，新玩家不再获得 |
| 顺序调整 | 只改数组顺序，星数存档零影响 |

## 8. 合规（保留红线，不扩展）

- ✅ 好友关系链走开放数据域，昵称头像走微信授权 + 隐私保护指引。
- ⚠️ 自定义昵称属 UGC，云函数写入前做内容安全检测（`msgSecCheck`），榜单不展示微信号/手机号。
- ❌ 禁止「分享加星」、付费买名次、利诱分享。
- ⚠️ 版号/防沉迷/类目口径会更新，以国家新闻出版署与微信开放社区最新公告为准。
