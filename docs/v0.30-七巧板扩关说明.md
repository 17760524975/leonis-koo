## 二、关卡怎么生成的

沿用项目既有范式（`tools/build_tangram7.js` 的 `grow()`）：**先摆出 7 块标准板的刚体装配（不切板），再由并集反算轮廓**。因此每关都自带精确标准解，判定必然通过。

与历史相比新增一步：**形状匹配**。对参考图 25 个图案各算一个形状签名（4×4 归一化 bbox 网格覆盖率 + 长宽比 + 凹角数 + 顶点数），在 2340 个合法候选剪影里做全局贪心分配，逐个挑「体态最接近」的那个，且互不重复。

匹配策略保证的是**体态**（横/竖、宽扁/细长、凹角复杂度），不是像素级轮廓：
- 鱼/乌龟/鲸鱼/狗熊 → 横向宽扁
- 鸭子/兔子/圣诞树/蜡烛 → 竖向细长
- 蝴蝶/爱心 → 左右展开
- 坦克/购物车/直升机 → 横向 + 侧向凸出

## 四、技术边界（重要）

**为什么不做照片图案的 1:1 复刻**

参考图是实物平铺俯拍，存在阴影、板厚、白边外扩、板间缝隙。实测把照片反解成精确七巧板解不可行，原因有三：

1. **分割不可靠**。用 `pyrMeanShiftFiltering` + Canny + distanceTransform 分 7 块，蝴蝶图案的 S 块面积只有 1.22u²（应为 2）、T5 只有 0.55u²（应为 1）、P 块吃掉了两块板。同色系相邻板（中间蓝方块 vs 左上蓝大三角）无法靠颜色分开。
2. **姿态拟合精度不够**。按面积/边长枚举 45° 姿态取 IoU 最优，全图平均 IoU 0.79，但可视化显示绿框与彩色板件明显错位（`tools/tanref2/fit_02.png`）。
3. **判定门槛是 0.99**。`js/judge.js` 要求 `coverage >= 0.99 && overflow < 0.01`，而连续坐标下降精修只能到 0.86–0.98，1/12u 网格吸附仅 7/25 自洽。七巧板顶点含 √2 因子，不落在简单网格上，网格吸附这个假设本身就不成立。

已尝试并否决的路线（研究件保留在 `tools/tanref2/`）：
- `solve25.js` 纯轮廓反解（`tools/tanref/solve7.js`）→ 全部 FAIL
- `assemble.js` 图像姿态约束装配 → FAIL
- `edge_assemble.js` 块边贴目标轮廓 → FAIL（轮廓边方向噪声大：17°/21°/56°）
- `edge2.js` 块间共享边 → 25 个全 0 解
- `refine25.py` 坐标下降 → 覆盖率 0.86–0.98
- `grid_snap.py` 1/12u 网格吸附 → 仅解出 7/25
- `exact25.py` 板边端到端精确装配 → 爱心 0.902 / 坦克 0.871 / 鸭子 0.844 可解，其余因姿态输入错误失败

**若要 1:1 复刻，需要**：矢量格式（SVG/AI）的图案、或正面无阴影的平铺高清图（每块板颜色差异明显且不与相邻板同色）、或直接给出每块板的 `(x, y, angle, flipped)` 坐标。
