> ① 字母关卡的 Y，竖干下方的直线还有错位（红框圈出）；
> ② 生肖关卡龙，尾巴部分的中三角位置太往上了，应该往下放。

两条是同一类毛病：**本来应该是一条直线的边上多了一个台阶**。所以修完不靠目测，
直接用「切片」把它们钉成不变量（见第五节）。

## 一、Y 的竖干：下半截整体缩进 12.76

### 1. 错在哪

Y 的竖干是「平行四边形 `P`（上半）+ 中三角 `T3` / 大三角 `T2`（下半）」拼的。量一下：

| 板 | 右竖边 x |
|---|---|
| `P`（上半） | **567.92** |
| `T2` / `T3`（下半） | **555.16** |

`P` 的右竖边是**对的** —— 它和右侧大三角 `T1` 的左腰完全共线（x 都是 567.92），
这是 Y 的骨架：右臂内侧那条竖线一路下来就是竖干的右边。

问题在下半截：`T2` 的尖角落在 `(555.16, 601.29)`，而 `P` 的右下角在 `(567.92, 614.04)`
—— 两者恰好都在同一条 45° 斜边上，只差 **12.76 / 12.75** 没顶到角。
于是剪影的右边缘在 y≈614 处向内跳了 12.76，再往下走，中间还留了一个 12×12 的小勾。

屏幕上 12.76 世界单位 ≈ 8.8 设计 px，在缩略图里就是一条明显的「错位线」。

### 2. 怎么修

把 `T2 / T3` **沿 45° 斜边**平移 `(+12.76, +12.75)`，让 `T2` 的尖角正好顶到 `P` 的右下角。

关键在「沿 45° 平移」这四个字：

* `T2` 的斜边原本与 `P` 的右下边共线，沿这条线滑 → **仍然共线**，不会开楔形缝、不会压叠；
* `T2` 的左上顶点原本落在 `T4` 的斜边上（左臂下沿），沿 45° 滑同样留在那条线上 → 左臂不断开。

修完：

```
竖干右边缘  x = 567.92   一条直线（478.28 → 806.04）
竖干左边缘  x = 375.92   一条直线（422.04 → 806.04）
竖干宽度    192（= 2u，不变）
```

代价是竖干整体右移 12.76、下移 12.75：X 方向 363 → 375.9，底部 793.3 → 806.0。
宽度没变、比例没变，只是把「错位」换成「对齐」。

### 3. 剪影

只改竖干那一段，其余 8 个点一个字节都没动（V 谷底那 0.5 的小折肉眼不可见，留着以免碰到别的关）：

```diff
- [567.63,614.13], [555.75,602.13], [555.25,602.25], [555.25,793.38], [363,793.38], [363,409.38]
+ [568,806.14], [375.82,806.14], [375.82,421.95]
```

点数 17 → 13，自交 0，面积外扩 0.269% → **0.234%**。

## 二、龙的尾巴：v0.52 的上滑滑过头了

### 1. 这是 v0.52 留下的

`docs/v0.52` 里记着：紫三角挪到平行四边形左侧后整条龙变成 993 宽，超出 1000 的卡纸，
所以把「绿中三角 `T3` + 粉小三角 `T4`」沿红色大三角 `T1` 的 45° 右腰**往上滑了 72 单位**。

上滑本身没问题（贴腰滑不开缝），但滑过头了：

| | 背线（`T2` 顶边） | 尾巴上缘（`T3` 顶边） | 差 |
|---|---|---|---|
| 参考图的原始位置 | 440.51 | 495.8 | 尾巴比背线低 55 |
| v0.52 上滑 72 之后 | 440.51 | **423.775** | 尾巴比背线**高 16.7** |

于是背线断成两截，在 x≈705 处错开 16.7，中间还多一个 16×16 的小勾 —— 用户说的
「中三角位置太往上」就是这个。

### 2. 怎么修

沿同一条 45° 腰**往下滑回 16.735**，正好让 `T3` 顶边 == `T2` 顶边。`T4` 坐在 `T3` 的顶边上，
跟着一起平移（顺手把 0.04 的历史缝也对齐）。

* 沿腰平移 ⇒ `T3` 的斜边仍与 `T1` 右腰共线，不开缝、不压叠（实测压叠 11 单位² = 0.007%）；
* 背线从橙色正方形一路直通到尾鳍根部，台阶与小勾同时消失。

### 3. 为什么不滑到参考图的原始位置

再往下 52 单位，龙会宽到 993（v0.52 的老问题），左右留白只剩 3.5 —— 贴卡纸边。
七块板尺寸是全局固定的（u=96，全 57 关共用一套托盘），**不能缩放**，只能动相对位置。
所以在「造型还原」和「塞进卡纸」之间取了一个可解释的点：**尾巴上缘与背线齐平**。
结果是 927 → **943.8** 宽，左右留白各 28.08（两边相等，不贴边）。

### 4. 剪影重写成「顶点精确并集」

龙的旧剪影走栅格描边（0.25 格 + 膨胀 1 格），所以到处是小折：`[809.91,287.97],[810.66,287.97]`
这种 0.75 的双点、`[688.41,424.22]` 这种 0.75 的台阶，一共有 25 个点。

这次和 v0.59 修蛇关一样，直接用**板件顶点**写剪影（16 点，不描边、不外扩）：

```
尾鳍顶 → 尾鳍斜边落点 → 中三角最右 → 中三角尖（尾巴 V 谷）→ 红三角右下 → 红三角左下
→ 后腿 → 正方形左下 → 平行四边形左下 → 紫三角左尖（头）→ 紫三角上顶点
→ 平行四边形右上 → 正方形右上 → 背线（抬 1.8）→ 背线直到尾鳍根部 → 回尾鳍顶
```

面积差：+235.9（栅格描边）→ **+2.5**（几乎等于板件并集），点数 25 → 16。
顺带整体左移 4.83 让左右留白相等。

## 三、顺手修掉的一个坑：`.gitattributes` 与生成脚本打架

`js/levels.js` 的 26 个字母、12 个生肖都是 `tools/build_*.js` 生成的，脚本的定位锚点
（`'  {\n    "id": 20,\n    "chapter": 2,\n    "name": "A",'`）按 **LF** 写；
而 `.gitattributes` 是 `* text=auto eol=crlf`，**每次 `git checkout` 之后文件是 CRLF**
→ 直接跑脚本会报「找不到七巧板第 20 关（字母 A）」。

两个生成脚本读文件时各加一句归一：

```js
let src = fs.readFileSync(LV, 'utf8').replace(/\r\n/g, '\n');
```

写出去仍是 LF，git 提交时按 `eol=crlf` 规范化，diff 不会炸。

## 六、风险

* Y 的竖干整体右移 12.76 / 下移 12.75，Y 因此比原来「窄一点、长一点」；宽度仍是 2u，
  比例没变（这是唯一能把错位消掉又不产生压叠的平移方向）。
* 龙的尾巴上缘与背线齐平后，「背线 → 尾鳍」是一整条直线，龙看起来比参考图更「平背」；
  参考图那种「尾巴低一截」的造型在 1000 宽卡纸里放不下（会到 993）。
* 这两关的 `parTime / parSteps` 没动：形状只平移了 12~17 单位，难度不变。
