# v0.46 · iPhone 17 顶部安全区适配 + 胶囊放大

## 用户反馈原文

> 「iphone17 页面兼容性有问题，顶部胶囊区域还有倒计时都被卡纸盖住了一部分，需要整体上移，
> 然后胶囊可以放大一点现在有点小」

## 根因：不是「位置偏低」，而是「卡纸顶写死、顶部栈跟着 safeTop 走」

对局页顶部有三样东西共用一条水平带：左上两枚余量胶囊（巧币 / 体力，竖排）和屏幕中线的倒计时胶囊。
它们的位置都是 `view.safeTop + 常数`，而**卡纸顶 `LAYOUT.BOARD.y` 是写死的常量**。

旧值 `BOARD.y = 176` 是按设计基准 `SAFE.top = 88` 定的。真机一旦安全区更大，两者就开始互相吃：

| | 公式 | iPhone 17 实际值 |
| --- | --- | --- |
| 缩放 | `scale = min(402/750, 874/1624)` | **0.5360**（宽受限） |
| 安全区顶 | `max(88, 62 / 0.5360)` | **115.7 设计 px** |
| 第二枚胶囊底 | `safeTop + 72` | **187.7** |
| 倒计时胶囊底 | `safeTop + 68` | **183.7** |
| 卡纸顶（旧） | 常量 | **176** |

两张都越界了 —— 体力胶囊被压 **11.7px**、倒计时被压 **7.7px**。

**而且是「盖住」不是「推挤」**：`renderPlay()` 里 `playHud(by)` 先画、卡纸后画，
卡纸把胶囊不透明地糊掉了。这也解释了用户截图里为什么体力那枚被吃得比倒计时多（187.7 > 183.7）。

> 关键约束：`safeTop` 以上是 iOS 状态栏 / 灵动岛，**不能再往上让**。
> 所以「整体上移」只能实现成「卡纸往下让」，而不是把顶部栈顶进状态栏 ——
> 旧代码的 `topShift = 8` 正是往上顶了 8px（胶囊顶沿本来就在 safeTop 之上 8px），
> 这一版一并改掉了。

## 改法

### 1. 卡纸顶按安全区自适应下移，**底边钉死**

```js
// config.js：设计基准回落到 216（比 176 低 40），h 842 → 802，bottom 仍 1018
BOARD: { x: 8, y: 216, size: 734, h: 802, bottom: 1018 }

// core.js resize()：
var needTop = view.safeTop + hudStackH() + (M.gapToCard || 0);
var nudge   = Math.max(0, Math.min(BOARD_MAX_NUDGE, needTop - BASE_BOARD_Y));
LAY.BOARD.y = BASE_BOARD_Y + nudge;
LAY.BOARD.h = BASE_BOARD_H - nudge;
```

`hudStackH()` = `topPad + rowGap + pillH` = `2 + 50 + 42` = **94**；`gapToCard` = **20**。
每次 resize 都从 `BASE_BOARD_Y/H` 重算（不是在上一帧结果上累加），转屏 / 切设备都不会漂。

**底部为什么必须钉死**：托盘里板件的散放位置是 `buildSet()` 时按 `TRAY.top/bottom` 一次算好的
（`pilePack()` 的结果是绝对设计坐标），`TOOL_Y` 也是模块加载时算好的常量。
卡纸一旦整体位移就会把这些全部带歪，而底部本来就留着约 200px 空白，
所以「从上面吃掉、底部不动」是唯一低风险的改法。

**盘面没有缩小**：`BOARD.y` 只是坐标原点，`size` 与 `WS = size/1000` 都没动，
轮廓和板件都走 `w2d()/h2d()` 映射 —— 卡纸变矮、变低，但拼图区一像素没少。

### 2. 胶囊放大一档

| 字段 | v0.45 | v0.46 | 说明 |
| --- | --- | --- | --- |
| `pillH` | 36 | **42** | +16.7% |
| `rowGap` | 44 | **50** | 两枚之间仍是 8px 缝 |
| `fontSize` | 24 | **27** | +12.5% |
| `subFontSize` | 17 | **19** | 分母「/16」 |
| `minFontSize` | 18 | **20** | 降字号兜底下限 |
| `maxW` | 127 | **146** | 32+146=178 < 倒计时左沿 255，净空 77 |
| `iconInset` | 21 | **23** | 图标中心距胶囊左沿 |
| `padL / padR` | 43 / 18 | **45 / 19** | 文字起点避开图标右沿（23+14≈37） |
| `coinScale` | 0.78 | **0.90** | 徽章直径 33×0.90≈29.7 / 42 ≈ 0.71 倍胶囊高 |
| `energyScale` | 0.70 | **0.82** | 能量珠略小一号保持从属感 |
| `topShift` | 8 | **0** | 上移量改由 `topPad` 正向表达 |
| `topPad` | — | **2** | 第一枚胶囊顶沿 = `safeTop + 2` |
| `gapToCard` | — | **20** | 胶囊底到卡纸顶的最小留白 |

### 3. 锚点统一

以前倒计时用 `safeTop + 40`、胶囊自己用 `topShift` 再往上顶 8px，**两条线本来就不一致**；
放大后高低差更明显。现在两边共用 `hudAnchorY()`：

```js
function hudAnchorY() {
  var M = LAY.HUD_MIN;
  return view.safeTop + (M.topPad || 0) + M.pillH / 2 + M.rowGap / 2;
}
```

`renderPlay` / `renderResult` / `renderFail` 三处 `playHud()` 也一并换过来。

## 五种尺寸实测

| 机型 | 屏幕 | safeArea.top | scale | safeTop | nudge | 卡纸顶 | 胶囊底 | 净空 | 卡纸底 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| iPhone 17 | 402×874 | 62 | 0.536 | 115.7 | 13.7 | 229.7 | 209.7 | **20.0** | 1018 |
| iPhone 15 / 16 | 393×852 | 59 | 0.524 | 112.6 | 10.6 | 226.6 | 206.6 | **20.0** | 1018 |
| iPhone 13 / 14 | 390×844 | 47 | 0.520 | 90.4 | 0 | 216.0 | 184.4 | 31.6 | 1018 |
| iPhone SE | 375×667 | 20 | 0.411 | 88.0 | 0 | 216.0 | 182.0 | 34.0 | 1018 |
| 设计基准 | 750×1624 | 0 | 1.0 | 88.0 | 0 | 216.0 | 182.0 | 34.0 | 1018 |

倒计时胶囊（高 56）底沿始终比胶囊栈更低 —— 三种机型的净空分别是 38 / 38 / 49.6 / 52，
全部 ≥ 20，**卡纸顶恒在两者之下**。

## 验收

`tools/verify_v046.js`（28 项，全绿）：

- **A** 配置数值与几何自洽：胶囊高/字号/宽度上限/图标比例、图标不越出胶囊左沿、
  文字起点避开图标右沿、卡纸 `y=216 / h=802 / bottom=1018`、进度条+托盘+工具栏一个没动；
- **B** 5 种机型逐一 `resize()`：`nudge` 公式成立、`胶囊底 < 卡纸顶` 且留白 ≥ `gapToCard`、
  `卡纸底 ≡ 1018`；并**反证**旧口径在 iPhone 17 上会越界 11.7px；
- **C** 真跑一帧对局页：巧币 / 体力 / 倒计时三个数字的 baseline 都在卡纸顶之上，
  关号仍在卡纸内，巧币在左半屏、倒计时在右半屏；
- **D** 三端 `core.js` / `config.js` 一致。

> 测试桩里补了一小段 CTM 跟踪（`setTransform` / `translate` / `scale` / `save` / `restore`）：
> 倒计时数字是先 `translate` 到胶囊中心再 `fillText(0, 0)` 画的，
> 只记原始参数会拿到 `(0,0)`，没法判断它到底在不在卡纸之上。

同步改动的旧断言（数值变了，口径不变）：

- `verify_v17.js`：顶栏中线改用与 `hudAnchorY()` 同一公式（不再抄 `safeTop + 40`）；
  `HUD_MIN` 关键值 + 「上移 8px」两条换成 v0.46 口径；
- `verify_v037.js`：只保留「`left=32` + 右锚定关闭」这条 v0.37 的真实成果，
  其余字段交给 v046；
- `verify_v09.js`：`BOARD.y ≤ 184` 改成「仍在原广告位起点 302 之上」，
  纸面高改成 `h === bottom − y` 的自洽校验（版本无关）。
