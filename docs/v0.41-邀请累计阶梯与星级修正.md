## 一、星级补差：改回 1 / 2 / 3

v0.40 我按「逐级 11 / 21、跨级 32」设的，用户纠正为 **1 / 2 / 3**。总额表跟着改成：

| 星级 | 应得总额 `starReward` | 逐级差价 |
|---|---|---|
| ★☆☆ | 21 | —（首通 21，沿用 v0.40 之前用户给的数） |
| ★★☆ | 22 | **+1** |
| ★★★ | 24 | **+2** |

跨级 1★→3★ = 24 − 21 = **3**，正好等于 1+2 —— 这次三个数字是自洽的，不需要再解释。

机制完全不变：`本局进账 = starReward[该关最高星级-1] - starPaid[关号]`，每关封顶 24，看视频 ×5 仍作用于当次进账、加成不写进已发账。存档迁移也照旧（老档按旧口径 2/3/5 记账）。

**连带影响**：关卡卡片上的「↑N」角标现在显示 `↑1` / `↑2`；结算页文案变成「升到 ★★ · 补差 +1 巧币」。数值小到这一步，它的意义更多是「让玩家知道还没打满」，而不是主要收入来源 —— 主要收入仍是首通 + 在线奖励 + 邀请阶梯。

## 二、邀请有礼重做

### 2.1 旧口径的两个问题

- **每天只能邀请一次**：`inviteDay === todayKey()` 就直接拦掉，玩家想多拉几个朋友都没门；
- **点一下就发奖**：分享即 +20 巧币 +1 道具，被邀请的人有没有真的玩、玩了多久，完全不知道。

### 2.2 新规则

1. **去掉每日限制**：一天发多少张邀请都行（只有 1.2 秒的防连点冷却）。
2. **分享不当场发奖**：每次分享只是往 `invitePend` 里压一张「待确认的邀请」。
3. **好友完成任意 4 关才算 1 位**：`INVITE.needCleared = 4`。
4. **8 档阶梯按累计人数发放**，每档只发一次，自动到账。

### 2.3 「好友完成 4 关」怎么判定

这是本轮最需要说清楚的地方。正式做法是后端在好友通关时回调邀请者；本项目**没有后端**，也读不到微信关系链里的关卡数（开放数据域只负责把榜单画到共享画布上，主域拿不到数据）。所以判定做成两级：

```js
function inviteConfirmed(ts) {
  // ① 宿主能判断就听宿主的（将来接后端，只改这一个函数）
  if (env.invite && typeof env.invite.confirmed === 'function') {
    if (env.invite.confirmed(ts)) return true;
  }
  // ② 没有宿主 → 本地模拟：邀请发出后 verifySec(60) 秒视为好友完成了那 4 关
  return Date.now() - ts >= INVITE.verifySec * 1000;
}
```

存档结构、发奖逻辑、面板 UI 全部按真实口径写，接后端时交互一行都不用改。

### 2.4 8 档奖励

| 档 | 累计人数 | 奖励 |
|---|---|---|
| 1 | 1 人 | 30 巧币 + 1 查找道具 |
| 2 | 2 人 | 20 体力 + 霓虹板件 |
| 3 | 3 人 | 水晶板件 + 泡泡漂浮背景 |
| 4 | 4 人 | 1 查找道具 + 10 体力 |
| 5 | 5 人 | 马卡龙板件 + 10 体力 |
| 6 | 6 人 | 1 查找道具 + 50 巧币 |
| 7 | 7 人 | 1 查找道具 + 花瓣飘落背景 |
| 8 | 8 人 | 荧光板件 + 1 查找道具 |

合计：**80 巧币 + 40 体力 + 5 个查找道具 + 4 套板件（霓虹 / 水晶 / 马卡龙 / 荧光）+ 2 套背景（泡泡漂浮 / 花瓣飘落）**。

两个实现细节：

- **体力允许溢出**：`addEnergy(n, null, true)`，满体力时 +20 也照加（16/16 → 36/16），与看视频、在线奖励同一口径 —— 否则玩家做完邀请反而被上限吞掉 20 点。
- **板件 / 背景走全局解锁表**：`grantItem('pstyle'|'bgfx', key)`，写进 `tangram_shop_v1`，四巧 / 七巧共用一份。这几样原本是 100 / 150 巧币的付费项，邀请直接解锁，等于给了一条免费拿皮肤的路径（也顺带验证了付费系统与免费发放不会打架）。

### 2.5 存档

```js
inviteCount: 0,   // 有效邀请人数（累计，跨天不重置）
invitePend: [],   // 待确认的邀请时间戳（发出但好友还没打完）
inviteGot: [],    // 已发放的档位编号，保证每档只发一次
```

老存档只有 `inviteCount` + `inviteDay`：**沿用 `inviteCount` 当起始人数**（老玩家邀请过的人不该清零），`inviteDay` 彻底作废。如果老玩家的 `inviteCount` 已经够几档、但 `inviteGot` 是空的，第一次打开面板会把对应档位一次性补发 —— 这是合理的：以前那套只给过 +20 巧币 +1 道具，远不够阶梯标准。
