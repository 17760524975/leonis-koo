## 一、为什么不能"照着画"，只能"反解"

手画走过一遍，失败了：七巧板的边只允许 0° / 45° / 90°，而插画里的动物是艺术化的连续造型，
对着图估坐标，最后拼出来必然要么有缝、要么压叠、要么某个角对不上 —— 因为**七块板的形状是固定的 6 种（两块大三角全等）**，
不是任意四边形。

所以走反解：**颜色是唯一可靠的"板件身份"来源**（用户给的那张映射表），
尺寸由图形总面积反推，角度/翻面由掩膜 IoU 决定，整体旋转单独估。

### 链路

| 步骤 | 脚本 | 做什么 |
|---|---|---|
| 1 | `tools/zodiac/ref.html` → Edge headless | 把桌面 webp 截成 `ref.png`（800×533，无缩放先染色） |
| 2 | `tools/zodiac/png.js` | 纯 JS PNG 解码（零依赖） |
| 3 | `tools/zodiac/scan.js` | 连通域找 12 个图形的 bbox（顺带滤掉两条边框噪声） |
| 4 | `tools/zodiac/extract5.js` → `extract6.js` | 逐色掩膜 IoU 拟合每块板：`sMul×8 角度×2 翻面` 粗搜 + 0.5px 平移细化 |
| 5 | `tools/zodiac/lattice.js` | 把"近似贴合"精化成"零重叠零缝隙"，再描出剪影 |
| 6 | `tools/zodiac/compact.js` | 对"太长"的图形做合法贴边挪块（龙） |
| 7 | `tools/build_zodiac_levels.js` | 写进 `js/levels.js`，生成 `splitLines` |

### 三个关键坑

**坑 1：插画里有些图形整体被画歪了。** 猴歪了 15.75°，兔 −1°，鸡 −0.75°。
直接拟合 IoU 只有 0.66~0.85，而且**角度会全部错位**。`extract6.js` 于是多了一个"整体旋转 δ"的搜索：
先在 −24°..24°（步长 1°）里粗搜，再在 ±1° 内以 0.25° 细化，目标函数是 7 块 IoU 之和；
定下 δ 后逐块求角度，**输出时角度扣掉 δ、位置绕图形中心反旋转 −δ** —— 等于把图形扶正。
扶正后 12 个 IoU 全部回到 0.84~0.95。

**坑 2：解析并集在"顶点相碰"处会自交。** 七巧板铺砌里两块板经常只共一个顶点，
这时求并集会产生零宽尖刺，`pointInPoly` / `segCross` 全部失真（蛇的轮廓 14 点却报越界 296）。
`tools/zodiac/union.js` 试过三种写法：
- 采样法（在边中点两侧取点判内外）→ 严格贴边时采样点会跨过真实缝隙，边界段被误判成内部边，并集塌成 3 个点；
- 半边配对消隐（边在其它板顶点处打断 → 端点聚类 → 同一对节点上 `a→b` 与 `b→a` 互相抵消）→ 用于**判断有没有内孔**，可靠；
- **栅格描边**（0.25 世界单位栅格 → 膨胀 1 格 → 边界边串环 → Douglas-Peucker）→ 用于**生成剪影**，12/12 严格包含。

膨胀 1 格是必需的：膨胀 0 格时"顶点相碰"的接触点在 4 邻域上不连通，环会断成几段（实测 12/12 全断）。
代价是剪影面积比板面积大 0.5%~0.7%（≈0.25 世界单位的一圈 ≈ 0.08 屏幕像素），肉眼不可见。

**坑 3：两块板只要"差不多贴上"，玩家就会看到白缝。** 拟合出来的坐标误差在 ±1px（≈0.05u ≈ 5 世界单位），
肉眼可见。`lattice.js` 用三步精化：
- **全局最小二乘**（`lsSolve`）：把「顶点重合」（2 个方程/对，权重 1.2）和「顶点落在邻板边上」（T 形接头，1 个方程，权重 0.65）
  写成 14 元线性方程组，正规方程 + 列主元高斯消元，再用 **6 轮 IRLS**（Huber 降权 `w *= 1/(1+(r/0.15)²)`）抗离群；
- **坐标下降松弛**（`relax`）：能量 = 压叠×400 + `min(板间距离,4)²`×2.5 + 极弱锚定；8 方向、步长 `[0.6,0.3,0.15,0.07,0.035,0.017]` 递减；
- **强制贴回**（`connect`）：离群板件沿最短缝隙贴到已连通板上，最多 8 遍。

每种方案（`ls / lsrelax / lscrel / connect / crelrel / relax`）都跑一遍，按 `面积差×10 + 越界 + 压叠×5` 择优。
12 关最终**面积差 0.00%~0.37%、压叠 0.0000u²、覆盖率 98.9%~99.7%**。

> 顺带修了自己一个 bug：`L.polyArea` 返回**有符号**面积，翻面的板是负的，
> 一开始直接求和导致 `sumA` 只有真实值的一半，覆盖率检查恒等于 0（"全绿"其实什么都没查）。
> 改成 `Math.abs` 之后才暴露出真正的 0.37%。

## 二、龙的 993 世界单位是怎么来的，又怎么解决的

七块板的尺寸是**全关卡共用一套托盘**，绝对不能缩放 —— 缩了托盘里的板就和剪影对不上。
所以图形多大就是多大。

参考图里龙是一张**长条**（993 × 444 世界单位，10.3u 长），蛇 924，马 835，猪 815。
放进 1000 世界单位的棋盘后，龙左右只剩 **3.4** 单位（2.5 设计 px）—— 等于顶在卡纸边上。

`tools/zodiac/compact.js` 的做法是**合法的贴边挪块**：
取下一块板，枚举剩下 6 块板的每条边 × 这块板的每条边 × 8 种朝向 × 2 个方向，
只保留「两条边长度相等且完全重合、与其它板零压叠、仍在棋盘内」的摆法，
按「外接框最长边最短」排序，并且**优先动最少的块**（动得越多离参考图越远）。

- 龙：把右上角那块小三角（T5）挪到正方形的边上 → **993 → 857**，留边 52px ✓
- 蛇：单块挪都省不下来（两块小三角左右并列，只挪一块另一个还在原地），
  成对挪能到 789，但**蛇的 S 形曲线会变成一个"山"字**，明显不像蛇了 —— 宁可保留原造型，
  它 924 宽、留边 26px，仍然看得出明显留白。

于是 `verify_v034` 的「剪影离卡纸边 ≥40px」对第 3 章放宽到 **24px**，前两章维持 40px。

## 四、验收

新增 `tools/verify_v051.js`（生肖专项，12 关 × 9 项）：

- 章节表自洽：三章 = 57 关、生肖 from 46 / count 12、id 连续 1..57、`completeSub` 报 57
- 每关 7 块、板块齐全不重复、面积和 = 16u²
- 零压叠（精确凸多边形求交面积 ≤ 单块 0.2%，实测最大 0.005%）
- 每块整块落在剪影内（`G.pieceInside`，容差 = 运行时 `C.JUDGE.fitTol` = 3.0）
- 剪影面积只比板面积大 0~1.5%（实测 −0.03%~0.69%）
- 剪影不出棋盘
- 运行时判定实测：`coverage ≥ 0.97`（实测最低 0.9893）、`overflow ≤ 2%`（实测 0.54%）、无真重叠对
- 反例：任意一块平移 40 单位必须判"没放对"
- 文案字段齐全（name / tip / hintTier / parTime / parSteps）

三个老脚本按新章节做了口径调整（都写在注释里）：

| 脚本 | 原口径 | 新口径 |
|---|---|---|
| `verify_v044.js` | 总关数 = 几何 + 字母；2 章；45 关面积误差 <0.25% | 总关数 = 几何 + 字母 + 生肖；3 章；生肖单列 <1% |
| `verify_v034.js` | 每关剪影离卡纸边 ≥40px | 几何/字母 ≥40px、生肖 ≥24px（龙 52、蛇 26） |
| `verify_v050.js` | 面积差 <0.2%、缝 <0.6% | 生肖章 1%、2%（剪影外扩 0.25 单位，全在最外圈） |
| `verify_tangram7.js` | 覆盖率 ≥99%、面积误差 <0.25% | 生肖章 ≥98.5%、<1% |

全量回归（44 个脚本）exit 0：`verify_v034`…`verify_v051`、`verify_tangram7`、`verify_tangram7_geometry`、
