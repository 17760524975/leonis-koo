# v0.56 · C / S 的内部缝隙（窄通道）修复

> 反馈：字母 C 和 S 中间还有一条缝，看上去像一条线。

## 一、这条线是什么

不是描边画错，是**板与板之间真的留了一条又长又窄的通道**：

| 字母 | 板对 | 间距 |
|---|---|---|
| C | T1（大三角）– T3（中三角） | **11.2** 单位 |
| S | T1 – T5（小三角） | **12.1** 单位 |

剪影是「七块板并集」描出来的，遇到这种通道就会顺着两边描进去，
于是图形中间多出一条 11 单位宽的白缝 —— 在 375pt 的屏幕上约 4px，看着就是一条线。

## 二、为什么之前的闭运算没解决

v0.54 加的是**形态学闭运算**（膨胀 K 格再腐蚀 K 格），它只能填「凹口」。
这种通道**两端是敞开的**（一端通向字母的开口），腐蚀会从开口端把它重新吃回去。

也试过「背景开运算 + 重建」：把背景腐蚀掉细通道，再以剩余背景为种子长回来。
但通道和外部背景是**同一个连通分量**，重建一长，通道也跟着长回来了。实测面积只增加 0.8%。

## 三、解法：从几何上把缝合上

新增 `tools/glyph/close_gaps.js`，在拟合结果（`letters_fit.json`）上做一步：

* 遍历每一对板，量出最短间距 d；
* 若 `0.02u < d < 0.19u`（0.3~3.0 px），把**面积较小的一块**沿最短连线平移 **90% 的 d**；
* 每次移动后用**真·凸多边形交集面积**校验：压到任何第三块板就撤销（1 单位² 以内算正常贴合）；
* 每块板总位移上限 **0.25u（24 世界单位）** —— 不加上限时，「多轮 + 双向」会把同一块板一路推着跑，造型就变样了（U 关曾因此压叠 0.14u²）。

只动 1u 以内，造型看不出变化，但缝是真的消失了；再描边时通道天然不存在。

顺带把另外 10 个字母里同类的小缝一起合上（V/W/Z 各 5 处、Y 4 处…），
所以这一版剪影点数从 **6~31 → 6~20**，整体更干净。

## 四、结果

| 指标 | v0.55 | v0.56 |
|---|---|---|
| C / S 内部通道 | 11.2 / 12.1 单位 | **0**（贴合） |
| 26 关剪影点数 | 6~31 | **6~20** |
| 危险间距（2~20 单位） | 3 处 | **0** |
| 剪影面积 − 板面积 | 0.15~0.31% | 0.00~0.13% |

目检：`C` 的青色/黄色、`S` 的青色/橙色都严丝合缝，黑线只走外轮廓。

## 五、验收

`verify_v053.js` 新增一条**数据级不变量**：

> 任意两块板的间距要么贴住（<2 单位），要么离得很远（>20 单位）——
> 不许存在 2~20 单位的窄通道（那会被描成一条线）。

加上原有的「I/S/X 无内孔」「26 关无自交」「点数 6~40」，
`verify_v050`（93 关）、`v044`（22 项）、`tangram7`（57 关）等全量回归仍全绿。
