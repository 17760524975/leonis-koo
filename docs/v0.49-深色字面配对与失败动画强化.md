# v0.49 深色主题的字面配对 + 失败动画强化

> 用户反馈原文（附深色排行榜截图）：
> 「再完善一下以下三个问题，因为我使用起来感觉和你做的有差别。
> ① 换了黑色的主题后，排行榜这边的字体显示颜色有冲突，改一下再检查下其他地方有没有类似的问题；
> ② 现在快速进入游戏主页几次音乐有重叠现象隔一会又好了，包括拼图游戏返回到关卡后不是也要切换主页音乐，多切换几次也有重叠音出现；
> ③ 游戏倒计时结束就算游戏失败，这时候需要设计一个失败动画配一个失败的音乐。」

这一版是 v0.47 / v0.48 的**返工**：用户明确说「和我做的有差别」，说明前两版改的位置对、但改的深度不够。逐条复盘如下。

## 一、深色主题下「浅底白字」

### 为什么 v0.47 没修干净

v0.47 的做法是「**在调用点判深浅**」：给 `surface` / `surfaceHi` / `chipOff` 这些**面**加了深色覆盖，然后每个画字的地方自己判断「这块底是深是浅、要不要换字色」。

这套做法的两个漏洞：

1. **面和字是两处独立维护的**。深色皮肤把 `COL.text` 翻成近白，而某个行底/资料卡/页签如果漏了深色覆盖、或用了半透明色叠出浅底，就变成白字压浅底 —— 昵称整行消失。这不是「某一行写错了」，而是**结构上允许出现错配**。
2. **「深色」的口径不完整**。`state.darkSkin` 只认「皮肤是深色」，但 `stars`（星夜流萤）/ `firefly`（萤火之森）/ `nebula`（星云流转）这三套**深色背景特效**会把页面底色换成深夜蓝，此时：
   - 背景已经是深色；
   - `renderPlay` 里的纸纹、糖果工具按钮、板件小样、进度格仍走「浅色分支」，出现一块块发亮的浅色补丁；
   - 卡纸上的墨色也跟着错判（纸面浅、墨色深或反之）。

### 这次的改法

**1）面和字配成对：新增 4 个「内容面字色」token**

```js
textOnSurface:   '#2C3A4B'   // 普通行底上的正文
textOnSurfaceHi: '#8F3A26'   // 高亮行底上的正文（暖褐）
textOnChip:      '#4E5E72'   // 灰底页签上的字
inkOnLight:      '#202A36'   // 兜底：万一面仍是浅色，用这支深墨
```

`COLORS`、`SKINS.dusk`、`DARK_PAL` 各写一份（浅色皮肤是深墨、深色是近白），**面在哪、字就在哪**，不再由调用点猜。

**2）运行时按对比度挑字色：`bestInk()` / `inkOnSurface()`**

```js
function inkOnSurface(highlight, sub) {
  var page = rgbOf(COL.bg) || black;
  var card = overRgb(rgbOf(COL.card), page);     // 卡纸叠在页面底色上的实际颜色
  var face = highlight ? COL.surfaceHi : COL.surface;
  var main = sub ? (COL.textOnSurface || COL.textSub)
                 : (COL.textOnSurface || COL.text);
  return bestInk(face, card, [main, sub ? COL.textSub : COL.text, COL.inkOnLight]);
}
```

关键在 `overRgb` + `bestInk`：**先把「面色叠在卡纸上、卡纸叠在页面底色上」算成实际 RGB，再用 WCAG 亮度比逐个比候选字色，取对比度最高的那一支**。于是：

- 面色是浅米 → 自动落回深墨（哪怕皮肤标记错了）；
- 面色是深石墨 → 用近白；
- 中间帧 / 旧包 / 第三方皮肤只覆盖了一半 → 也不会出现「字消失」。

配套 `rgbOf` / `relLum` / `contrastOf` 四个纯函数，没有任何变量捕获，验收脚本可以直接拿去做数值断言（见下文）。

**3）排行榜行、页签、资料卡全部改吃配对字色**

`rankRow()` 的昵称/名次/关卡数不再直接拿 `COL.text`：

```js
var rowBg  = highlight ? COL.surfaceHi : COL.surface;
var rowInk = inkOnSurface(highlight, false);
var rowSub = inkOnSurface(false, true);
var valInk = highlight ? bestInk(rowBg, COL.card,
                [COL.accentText, COL.textOnSurfaceHi, rowInk]) : rowInk;
```

页签选中 / 未选中各走一次 `bestInk`；`renderSettings()` 的资料卡昵称、状态行、改昵称、错误文案同样换成 `cardInk` / `cardSub`。

**4）好友榜（开放数据域）也要配对**

开放数据域是独立的 JS 环境，拿不到主域配色，只能经 `postMessage({pal})` 传过去。旧版把 `text` 传过去当行字色 —— 主域变深色后 `text` 是白的，而行底仍是浅米，好友榜整行同样会消失。现在主域额外传 `rowText` / `rowSub`，`openDataContext/index.js` 里名次走 `rowSub`、昵称与关卡数走 `rowText`。

**5）统一深浅口径：`state.darkUi`**

```js
state.darkSkin = !!sk.dark;                       // 皮肤本身是深色
state.darkFx   = !!(CL.BG_FX[bgFx] && ...dark);   // 背景特效是深色
state.darkUi   = !!(state.darkSkin || state.darkFx);   // 组件一律用这个
```

把 core 里 22 处只判 `state.darkSkin` 的分支全换成 `state.darkUi`，包括：纸纹（`board_paper` 浅色图 vs 深色纸面）、`inkOnCard`、糖果工具按钮色、板件小样底、进度格、HUD 胶囊、主页光斑、关闭钮。**纸面和墨色必须同进同退** —— 纸面改判 `darkUi` 后，`inkOnCard` 也跟着改，否则会出现「深纸配深墨」。

改完用截图逐屏核对（21 张，见 `tools/shot_v49.js`）：夜间护眼排行榜 / 暖木排行榜 / 星夜特效排行榜 / 连胜榜页签 / 排行榜失败态 / 设置页资料卡 / 主页 / 对局页 / 关卡列表 / 结算 / 提示 / 提示卡 / 皮肤 / 在线奖励 / 邀请 / 体力 / 失败页四个定格。

其中**邀请有礼**又挖出一处同类：进度条轨道在深色皮肤下是**浅半透明**（`rgba(180,196,236,0.22)`），而「0/1」这组数字写死用 `COL.textSub`（浅灰），对比度只有 **1.02:1** —— 深色下几乎是个空条。改为按轨道实际叠色挑字（`bestInk(COL.track, ...)`），过半（金渐变上）仍用深棕 `btnText`。

## 二、快速切页时的 BGM 叠音

### v0.47 的修法为什么还漏

v0.47 已经做了「代际清场」：`homeStart()` 在开闸前同步停掉上一代的所有振荡器。但**两代仍共用同一张音频图**：`homeGate`、`homeDelay`、`homeFb`、`homeWet` 是模块级单例。

问题出在回声环：

1. `homeStop(soft)` 把 `homeGate` 从 1 淡到 0，同时给振荡器排 `stop()`；
2. 但 `delay → fb → delay` 这条反馈环里**还留着上一代的尾音**（`delayTime` 0.34s、`feedback` 0.24，尾音能拖一两秒）；
3. 此时 `homeStart()` 把 `homeGate` 拉回 1 —— 反馈环里上一代的尾音被**同一只闸门**重新放大出来，听起来就是「新旧两首叠在一起，过一会儿又好了」（等尾音自然衰完）。

所以「停振荡器」不够，**共用闸门**才是根因。

### 这次的改法：一代一图，旧代整图 disconnect

每代创建一个独立的音频图，闸门、回声环、振荡器全在里面：

```js
function createHomeGen() {
  var gen = { osc: [], gate: null, lead: null, delay: null, fb: null, wet: null,
              seq: null, watch: 0, stopTimer: 0 };
  gen.gate = AC.createGain();  gen.gate.gain.value = 0;   // 新代从静音开闸
  gen.gate.connect(bgmGain);
  gen.lead = AC.createGain();  gen.lead.connect(gen.gate);
  // 回声环挂在这一代的 lead 上，不跨代
  gen.delay = AC.createDelay(1.0); gen.fb = ...; gen.wet = ...;
  gen.lead.connect(gen.delay); gen.delay.connect(gen.fb); gen.fb.connect(gen.delay);
  gen.delay.connect(gen.wet);  gen.wet.connect(gen.gate);
  return gen;
}
```

- `homeStart()`：`if (homeGen) homeStop(false)` → `flushHomeDead()` → `createHomeGen()` → `gateTo(1)`；
- `homeStop(soft)`：清定时器 → `homeGen = null` → 旧代淡出后进 `homeDying[]`，到点由 `stopHomeGen()` **把整张图里所有节点 `disconnect()`**；
- 旧代的回声环随图一起断开，**没有任何节点还能接到新代的闸门上**；
- `homePartial()` 清理单个泛音时同步维护 `homeGen.osc`，`bgmInfo()` 暴露 `live` / `dead` 两个计数供探针读取。

预览端（`preview/js/game.js`）对称实现，`verify_audio.js` 第 13 节把「共用旧图」的结构直接列为禁止项。

实测（`tools/verify_audio.js`）：快速进出主页 8 次，**同时发声的振荡器峰值 = 27，与单代基线完全相等**，`dead = 0`；慢速切换后仍是 `home=true / gate=1`。

## 三、倒计时归零的失败动画 + 失败音乐

v0.48 有了骨架，但用户「感觉差别不大」，实测确实有两处塌陷：

- 红心用 `easeOutBack(t/heartMs)` 从 0 开始长 —— **第 0 帧尺寸为 0**，失败瞬间屏幕上只有一圈碎片，心要 200ms 后才出现；
- 卡片 `globalAlpha` 从 0.35 渐变到 1，半透明期间**关卡的虚线轮廓直接透到按钮上**，两套 UI 叠在一起。

### 时间轴（`FAIL_ANIM`）

| 时间 | 画面 |
| --- | --- |
| 0 – 360ms | 红色径向暗角 + 全屏红闪（`flashMs = 360`）；14 片心碎碎片从中心 `easeOutCubic` 飞散到 900ms |
| 0 – 820ms | 「时间到！」横幅从上方砸下（带 `Math.sin(t/22)` 屏幕震动），580ms 起淡出、**820ms 前退干净** |
| 0 – 460ms | 「挑战失败」四字定格（深色胶囊托底），460ms 起退场 |
| 460 – 900ms | 复活卡片下滑 + 0.94→1 缩放进场（`cardDelay=460` / `enterMs=440`） |
| 700ms 起 | 卡片内文案淡入（`contentA`：`enter` 过 0.55 开始淡入、0.9 全显，即 700→856ms），先出「已经连胜 N 关了」，再出按钮 |
| 0 – 700ms | 大红心：起手就是 **72% 尺寸**（`0.72 + 0.28·easeOutBack`），从屏幕中心平移到卡顶；280–1150ms 画裂纹 |

四条硬约束：

1. 所有变换包在 `save/restore` 里，动画结束后与静态版**逐像素相同**；
2. 动画期间**不注册热区**（`hitOK = enter >= 1`），避免点到还没落位的按钮；
3. `state.failT` 只在 `overlay === 'fail'` 时推进，`reduceMotion` 直接跳过整段；
4. 失败卡先铺一层「`COL.card` 与底色合成后的**实色**」再 `drawCard` —— 卡纸本身是 `rgba(...,0.96)`，不铺实色底座的话，关卡虚线在动效期间仍会隐隐透出来。

### 失败音乐

`sfx_timeup` 在 v0.48 的基础上再做厚（纯合成、零文件）：

```js
strike(82.41, 1.05, 0.20, SFX_MAT.wood, 'triangle');   // 低频落地
noiseBurst(0.18, 0.13, 220, 0);                        // 起手噪声瞬态
// A 小调下行：A4 → F4 → D4 → A3，每音错开 190ms
[440.00, 349.23, 293.66, 220.00].forEach((f, i) =>
  strike(f, 0.46, 0.13 - i * 0.014, SFX_MAT.bell, 'sine', i * 0.19));
strike(110.00, 1.05, 0.09, SFX_MAT.wood, 'sine', 0.62); // 收句
```

增益 `sfxGain.sfx_timeup` 0.85 → **0.95**，并在 `failLevel()` 里补一次 **24ms 重震动**（与低频落地对齐）。播放顺序仍是 `halt()` → `play('sfx_timeup')`：先停关卡曲再播失败乐句，`halt` 不改 `bgmScene`，复活时 `setLevelScene()` 自然恢复。

## 五、已知折衷

- **弹层卡纸仍是 `rgba(...,0.96)`**，深色背景下主页大标题会在卡片顶部留下 4% 的浅色残影（排行榜那张最明显）。这次只给**失败卡**铺了实色底座（因为它有动画、贴近关卡虚线），其余弹层保持原样，避免一次性改动所有 sheet 的观感。
- `inkOnSurface()` 每次调用要解析 4~6 个颜色串并算亮度比。排行榜一屏 7 行 × 3 处、每帧 60fps，实测对帧率无可见影响（这些值只在 `!state.reduceMotion` 的静态版面上反复算，且都是短字符串解析）；若以后列表更长，可以把结果按「皮肤 + 高亮」缓存一张小表。
- 失败页 0–460ms 有一段「卡片未出、只有心与横幅」的空窗，是刻意的定格；若嫌长，改 `FAIL_ANIM.cardDelay` 即可，`verify_v049` 的 D 段会跟着校验。
