## 一、覆盖率永远差最后一点（用户点名「普遍问题」）

### 为什么旧判定必然卡住

旧判定是**栅格覆盖率**：先把剪影和板件按 2 世界单位栅格化，再算 `覆盖格数 / 目标格数 ≥ 0.99` 且 `溢出 < 0.01`。

七巧板的板边一半是 45° 斜边，两块板的斜边拼在一起时，判定栅格上**永远有一格既算 A 也算 B、或者两边都不算**：

- 45° 接缝在 2 单位的栅格上是一条锯齿，锯齿内侧的格子被两块板各占一半 → 计入"重叠"，外侧的格子两边都不到 50% → 计入"漏掉"；
- 实测标准解（题库里那套严格解）自己也只有 **99.67% ~ 100.41%**；
- 玩家用手指拖，落点再有 1~2 单位误差，就稳定落在 98~99% —— 于是"最后一点"永远补不上。

这不是"某关的数据不对"，而是**栅格口径和七巧板的几何不兼容**，所以用户感觉"普遍"。

### 换成用户提的思路：整块落位

用户建议"只要完全在拼图区域内、没有超出、没有和别的板重叠就高亮整块"，这一版就按这个口径重写 `runJudge()`：

1. **逐块整块判定** `G.pieceInside(poly, outline, holes, tol)`
   - 每个顶点都在剪影内（内孔按 evenodd，顶点不能落进内孔）；
   - 每条边与剪影边不"穿越"（用容差 3.0 世界单位吸收手指误差）；
   - 该块自身不进内孔。
2. **两两不压叠** `G.convexOverlapArea(a, b) ≤ 单块面积 × 2%`
   - 用 Sutherland–Hodgman 求两凸多边形的交叠面积（7 块板都是凸的，直接可用）；
   - 允许 2% 的容错，否则玩家手一抖就判失败。
3. **覆盖率只做兜底**：整块都在里面、彼此不压叠，天然就铺满了；`minCoverage` 从 0.99 降到 **0.94**，只在"7 块都判定就位但中间还漏一大块"这种数据错误时才拦。

于是"最后一点"这个状态**在物理上不存在了**：一块板要么整块在里、要么不在。

### 配套两件事，缺一不可

**① 进度条改语义：从"覆盖百分比"改成"已就位块数"**

旧进度条显示 `cov`（栅格覆盖率），收官时就是那条永远差一点的绿条。现在：

```js
var fitN = 0;
for (var fq = 0; fq < r.fits.length; fq++) if (r.fits[fq]) fitN++;
var progTo = DS.pieceOrder.length ? fitN / DS.pieceOrder.length : 0;
```

文案也从「覆盖」改成「**已拼**」—— 5/7 就是 5/7，不再是 71.4%。

**② 新增"标准解磁吸"** —— 只换判定还不够：玩家的手放不到 0.2 世界单位的精度，而"整块在里面"要求边不穿轮廓。所以 `snapPiece()` 从三层变四层：

| 优先级 | 吸附 | 触发条件 |
|---|---|---|
| 1 | **标准解**（新增） | 距标准解质心 ≤ `C.SNAP.solDist = 120` 世界单位（≈4 手指像素）、角度差 ≤ `solAngle = 14°`、手性一致 |
| 2 | 顶点 | 顶点距 ≤ `C.SNAP.vertDist` |
| 3 | 边 | 边距 ≤ `C.SNAP.edgeDist` |
| 4 | 网格 | 半格吸附 |

手性判定用 `flipSymmetric(id)`：把 `LOCAL[id]` 逐点做 `(-x, y)` 看是否还是同一集合。T1/T2/T3/S/T4/T5 都是轴对称的，**只有平行四边形 P 有手性** —— 对 P 必须翻转态也一致才吸，否则会把 P 吸成镜像（那就再也拼不上了）。

> 磁吸半径 120 是权衡：太小（<60）玩家还是吸不到；太大（>160）会"抢"，相邻位置的两块板互相抢落点。

## 二、叠放层级：后放的盖住先放的

### 问题

`state.pieces` 的数组顺序是出题顺序（`pieceOrder`），绘制和命中都按数组序 → 小三角形永远画在大三角形**下面**，被完全盖住看不见（用户截图中"选中了却找不到板"）。

### 改法

- 板件加 `p.z`，落板时 `p.z = ++state.zSeq`（`state.zSeq` 只在 `setupLevel` 重置）；
- 新增 `boardByZ()`：返回按 `z` 升序的数组，**绘制顺序 = z 升序** → 后放的在上面；
- 命中判定 `playHit()` 反过来按 z **降序**取第一个命中的 → 点到的就是看到的那块；
- 拖动中的那块永远最后画（`dragging` 单独一支），保证拖起来不会被压住。

这条和"整块落位"是同一个体验闭环：**看得见 → 拖得动 → 放得准 → 立刻算数**。

## 三、提示道具：放对之后金色提示必须消失

### 问题

`state.hint` 只在"点了提示"和"再点一次道具"时被清，摆对位置后不清 → 金色高亮一直亮着，看起来像"用了没效果"，也没法用下一次。

### 改法

`drawBoardPiece` 之前插一段实时判定（不能等 `runJudge`，那是每 6 帧一次、且有缓存）：

```js
var hpz = pieceOf(state.hint.id);
if (!hpz) state.hint = null;
else if (hpz.onBoard && (hpz.fit || pieceFit(hpz))) state.hint = null;
```

关键是 `hpz.fit || pieceFit(hpz)`：`p.fit` 是上一次判定的缓存，玩家可能在两次判定之间就摆好了，所以这里**实时再算一次** `pieceFit`（单块的开销可以忽略）。

提示清掉后 `state.hintTier` / `hintUsed` 不动，道具余量本来就已扣减，所以"下一次提示"直接可用。

## 四、几何关卡补图案：19 关

### 怎么找的

七巧板的 7 块板只能拼出有限种"外轮廓"，与其手工画，不如**穷举 + 筛选**：

1. 「边对边贴合」装配的 DFS：每步把一块板贴到当前外轮廓的某条边上，8 个朝向 × 2 个翻转；
2. 关键剪枝：**凸包面积 ≤ 16u²**（总面积）—— 没有这条，搜索 3 分钟跑不完；加上后 6 秒、10.9 万节点、146 个装配解；
3. 用 `normCycle()`（先统一绕向，再 4 个旋转 × 全循环移位取字典序最小）做形状指纹去重 → 146 个解收敛成 8 个形状；
4. 再用 `grow()`（随机采样 + 拒绝重叠）补 4 个有辨识度的凹形。

一共 **12 个新关**：直角梯形、斜梯形、五边形、长六边形、长梯形、切角六边形、斜方六边形、凹边菱形、凹底方形、盾形、纸飞机、折纸箭。

顺手删掉 3 个"同一轮廓转个方向"的凑数关：大三角·立、平行四边形·竖、凹五边形·横。

### 一个必须记住的坑

`tools/build_tangram7.js` 内部用 `U = 107`（历史原因），而题库数据集的 `unitScale = 96`。**两者不能混用** —— 反解板件状态（`recoverState`）时如果拿 107 去算 `LOCAL`，会报"无法反解 T1"。新关的生成脚本 `tools/add_geo_levels.js` 里全部用 `SET.unitScale` 重算了一份 `LOCALW`。

## 六、字母"错位和有缝隙"的核查

这是这一版花时间最多的一条，结论和改法分三步。

### 第一步：先量，别猜

写了 `tools/gap_audit.js`：对每关的 21 对板件算「顶点到对边」的最近距离，落在 `0 < d < 45` 世界单位的就是"本该贴合却留了缝"。

```
K  #30  maxGap=39.30  V #41 43.50  F #25 39.26  I #28 29.36
H  #27  maxGap=23.69  G #26 17.14  Y #44 16.96
其余 19 个字母：maxGap ≤ 0.83   几何 19 关：0.00（除 1 处设计凹口）
```

换算：棋盘宽 ≈ 330pt 对应 1000 世界单位，1 单位 ≈ 0.33pt。所以 **20 单位 ≈ 6.6pt、43 单位 ≈ 14pt** —— 这两档肉眼就是"一条白线"和"一道缺口"。剩下 19 个字母的 0.83 单位 ≈ **0.27pt**，是亚像素级，渲染层看不出来。

### 第二步：为什么不能"把板挪过去"

试过三条路，都走不通，记在这里免得以后再踩：

1. **`stitch()` 最小二乘缝合**（库里已有）：只认"平行边 + 重叠跨度 ≥10"的接触。这 7 关的缝大多是 **45° 楔口**（两条边互相 45°，`|cross| = 0.707`），根本没有平行边可对，缝一个都不动（V 的 43.50 → 43.50，分毫未变）。
2. **力松弛**（每块板的 x/y 当变量，近邻相吸 + 重叠相斥）：缝能收到 1~2，但代价是**板被拽离原位 50~64 单位**，字母直接变形；而且收完的位置不再"边对边"，并集串环失败率飙升（面积误差 20%~95%）。
3. **换成精确铺满**：用 `ntri` 小三角做 exact cover，`tiled3.json` 里 26 个字母**都能铺满**，但那些解里板与板只共顶点、不共边，画出来是散块（见图 `tools/out/calib45.png`），根本不像字母。

根因是**几何上做不到**：七巧板外角只能是 45° 的整数倍，而字母的笔画是等宽的。想拼一个笔画宽 w、高 4w 的 H，两块大三角（每条直角边长 2√2u）就占掉 8u²，剩下 5 块凑不出第二根竖笔。`tools/alpha/README-字母关卡.md` 在 v0.34 就写下过同样的结论。

### 第三步：能修的分两类修

**① 亚像素细缝（19 个字母 + 几何关）：渲染层加"同色外扩"**

相邻两块板各自的深色描边叠在一起，本来就会画出一条比缝宽得多的深线。`C.PIECE.seamBleed = 1.2`：已就位的板先沿自身轮廓描一圈**同色、加宽 2.4 设计 px** 的边，再描正常深边；这一圈裁在剪影轮廓内（含内孔 evenodd），所以不会在剪影外面撑出彩色毛边。

**② 真裂缝（G / H / K / Y）：`gapFill` 补块**

这 4 关的裂缝是"又长又窄"的内部裂缝（平行边、重叠跨度 136~192、缝宽 17~50），补起来不会改变字形：

- `tools/make_gap_patches.js` 逐对找"最近的一对边"，平行的按 28 单位一段段铺凸四边形、45° 窄楔口（≤26）只在最窄处补一小片，**跨度 <50 的平行缝一律不补**（那是字母自己的凹口，补了等于往外长肉）；
- 每块补块的颜色取"离它更近的那块板"，看上去就是那块板的延伸；
- 写进 `levels.gapFill`（G 6 块 / H 14 块 / K 1 块 / Y 1 块，共 22 块）；
- `core.js` 只在**补块所属的板已就位**时才画 —— 否则会出现一块悬空的彩色楔块。

补完再看 H：左竖笔那条贯穿到中心的斜白线没有了，竖笔是连续的一整块（见 `tools/out/gap_H.png`）。

### 还剩下的（坦白说）

F / I / V 三关的缝是**宽的 45° 缺口**（29~44 单位），补了会明显改变字形，所以这一版没补；它们看上去就是"两块板在一个点上相接"，属于字母自身的造型，不影响判定和拼合。要彻底消掉只能重画这三个字母的装配，留给下一版。
