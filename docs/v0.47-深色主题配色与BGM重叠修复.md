# v0.47 深色主题配色修复 + BGM 快速切页重叠修复

> 本版处理用户两条反馈：① 换黑色主题后排行榜字体颜色冲突，并检查其它浮层；② 快速进出主页 / 关卡时音乐重叠，过一会又自己好了。
>
> **注意**：用户同一条消息里的第 ③ 项「倒计时归零的失败动画 + 失败音乐」本次尚未实现，留待下一版。

## 一、深色主题配色冲突

### 根因

`refreshPalette()` 在深色皮肤下会把正文色 `COL.text` 改成近白（`#F2F5FF`），但浮层里若干内容块此前是**写死的浅米色**：

```js
ctx.fillStyle = highlight ? '#FDE7DF' : 'rgba(246,243,238,0.95)';  // 排行行
ctx.fillStyle = 'rgba(247,243,236,0.95)';                          // 设置页资料卡
ctx.fillStyle = 'rgba(255,255,255,0.92)';                          // 关闭圆钮
ctx.fillStyle = state.rankTab === i ? COL.gold : 'rgba(240,235,226,0.95)'; // 页签
```

于是「白字压浅底」，昵称整行消失 —— 用户截图里排行榜只看得见名次和关卡数，正是这个原因。

### 改法：语义化 token

在 `COLORS` 增加 6 个 token，`COLORS`、`DARK_PAL`、`SKINS.dusk` 三处各自给值：

| token | 用途 | 浅色 | 深色 |
|---|---|---|---|
| `surface` | 浮层内容块（排行行 / 资料卡 / 空态块） | 米白 `rgba(247,243,236,0.95)` | 半透明白 `rgba(255,255,255,0.09)` |
| `surfaceHi` | 高亮块（自己那行 / 选中卡） | `#FDE7DF` | `rgba(255,190,140,0.16)` |
| `chipOff` | 未选中页签 / 分段控件 | `rgba(240,235,226,0.95)` | `rgba(255,255,255,0.10)` |
| `disc` | 卡片外的圆形关闭钮 | `rgba(255,255,255,0.92)` | `rgba(255,255,255,0.16)` |
| `accentText` | 高亮数值字 | `#E2624A` | `#FFC98A` |
| `dangerText` | 错误提示字 | `#E5484D` | `#FF8B8B` |

表层统一走 token 后，正文色跟着 `COL.text` 走即可，每个调用点不再判深浅。另加 `pillBg` / `pillStroke` 让倒计时胶囊在深色下翻成深底浅字（浅色下保持原样），避免它成为深色页面里最亮的一块、也与左侧两枚深色余量胶囊风格一致。

### 全浮层审计

用 `tools/shot_v47.js` 逐屏拍了 12 张深色 / 浅色对照图：排行榜（主线 / 好友 / 加载失败）、设置页、在线奖励、邀请有礼、皮肤面板、结算页、对局页、失败 / 复活面板、免费体力、关卡列表、主页、提示面板。除上述四处外未发现新的同类冲突。

### 好友榜开放数据域

微信开放数据域是独立上下文，拿不到主域 `COLORS`。此前 `miniprogram/openDataContext/index.js` 自带一份写死的浅色配色，切到深色主题时「好友榜」页签会突然出现一大块浅底。

现在主域在 `env.friend.show()` 时把主题色一并 `postMessage` 过去，开放数据域按收到的 palette 重画；奖牌页数字改用「深底 → 白字 / 浅底 → 深字」的自适应取值。

## 二、BGM 快速切页重叠

### 复现与度量

`tools/probe_bgm.js` 用音频桩数「仍在时间轴上、尚未到 stop 时刻」的振荡器：

- 基线（只进一次主页）：**27 个**
- 快速进出 8 次（间隔 60ms）：峰值 **213 个** ≈ 8 代旋律同时响
- 等 190ms 后回落至 27 个

与用户描述「快速进入几次有重叠，隔一会又好了」完全吻合。

### 根因

主页曲的振荡器是提前一小节排进 WebAudio 时间轴的。`homeStop(soft)` 只做两件事：

1. 把淡出闸门 `homeGate.gain` 在 150ms 内拉到 0；
2. **190ms 后**用 `setTimeout` 硬停上一代振荡器。

如果在这 190ms 窗口内又 `homeStart()`，`gateTo(1)` 把闸门拉回 1 —— 上一代尚未走完的音符重新出声，和新排的一整小节叠在一起。旧代码用局部 `dead` 变量 + 裸 `setTimeout`，新起播时根本不知道有上一代存在。

### 改法：代际清场

两端（`miniprogram/game.js`、`preview/js/game.js`）对称改造：

- `homeDead[]` + `homeDeadTimer`：持有「正在淡出、等待硬停」的上一代振荡器；
- `flushHomeDead()`：**同步**清掉定时器并 `stop()` 全部代际振荡器（不传参数 = 立即停，尚未到 `start` 时刻的音符等于永远不出声）；
- `homeStart()` 在 `gateTo(1)` / `gain.value = 1` **之前**先调 `flushHomeDead()`，保证闸门重开时时间轴上只有这一代；
- `homeStop()` 把上一代挂进 `homeDead`，`setTimeout` 只负责收尾；更早的一代（极快连切）直接同步停。

`bgmInfo()` 额外暴露 `live` / `dead` 计数，便于验收脚本断言。

### 验收

`tools/verify_audio.js` 增加断言：快速切页后 sounding 振荡器数必须保持在基线附近，且两端源码都含 `flushHomeDead()` → 闸门复位 的先后关系。修复后探针数值稳定在 27，不再累积。
