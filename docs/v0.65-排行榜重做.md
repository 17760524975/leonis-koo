## 2. 榜单口径

| tab | 名称 | 排序键（优先级从高到低） | 主值 | 副信息 |
|---|---|---|---|---|
| 0 | 全服榜 | `stars ↓ → cleared ↓ → updatedAt ↑` | `★N` | `通关 M 关` |
| 1 | 好友榜 | 同上，数据来自微信开放数据域 | `★N` | `通关 M 关` |
| 2 | 本周榜 | `weekStars ↓ → streak ↓ → weekCleared ↓ → updatedAt ↑` | `★N` | `连胜 S · 本周 M 关` |

- **连胜榜下线**：`streak` 退成本周榜的次键，不再是独立页签。旧「tab 2 = 好友」整体左移成
  **tab 1 = 好友**、`tab 2 = 本周`，`rank_t1 → 好友`、`rank_t2 → 本周`（对外埋点名同步）。
- **名次不是 `index + 1`**：同分不同次键时名次必须分开算。云函数用复合 count：
  `where(main > mv).count()` + `where(main == mv, second > m2).count()` + 1，
  不能只按单字段数（否则同星数的人会挤在同一个名次上）。同分完全相等时按 `updatedAt` 升序，
  **早到者靠前**，名次才稳定、翻页也不跳。
- **满星上限**：`stars` 夹 300（93 关 × 3 星 + 3 关余量）、`cleared` 夹 120。

## 3. 点开卡顿：三个原因，逐个干掉

用户反馈「性能优化之后排行榜点开反而卡」。实测（`verify_v062` 的绘制计数 + 真机录屏）定位到三条，
都不是"画得多"，而是**画得贵的恰好都在这一屏**：

1. **每一行一个 `shadow(10, 4)`** —— 7 行列表 + 我的名次卡 = 8 次 CPU 高斯模糊，一把全在首帧。
   → 行阴影全部删掉，改用 **1px 描边**（`lineWidth 2` + 金 55% 透明）交代边界。视觉几乎无差，成本归零。
2. **v0.62 的「静态浮层跳帧」白名单里有 `rank`，而入场动画从不置 `dirty`** ——
   动画只在第一帧画了一次，之后 1 秒内一次都不重画，于是「啪」一下跳到终态，肉眼看就是卡。
   → **这一版直接取消入场动画**：`dy = 0`，一帧定版。排行榜不是高频页，动画带来的收益远小于
   它引发的重绘（和"跳帧"误会）。
3. **头像 `onload` 不通知重绘** —— 图晚到只能等下一条保底心跳重画，7 张头像集体闪一次。
   → `wxprofile.js` 加 `imgListeners`，`img.onload` 里 `notifyImg()`；`core.init()` 注册
   `PROFILE.onImg(() => state.dirty = true)`。谁到谁画，不再集体补帧。

**结论（写进项目习惯）**：静态浮层宁可**不做动画**，也不要"动画 + 节流重绘"两套机制打架。
`verify_v062` 里那条「静置 160ms 内零重画」的断言现在是**真绿**（动画在时 draws=1540）。

## 4. 周星：客户端兜底 + 云函数权威

总星数只升不降（老玩家不掉星），所以「本周新增」必须是独立账本 —— 否则没法表达"重玩已满星的关也算"。

**计分口径**：`weekStars` 按**本次星级**累加；**同一关、同一天只取最高一次**（满星老玩家重玩 3★ 也计 3★）。

链路：

```
win() → recordWeekWin(lv, stars)
        ├─ 本地账本 save.weekSeen[dayKey][uid] = max(旧, 本次)
        └─ save.weekQ.push({ uid, rev, stars, day })     // 待上行，上限 40 条
collectCloud().stats.weekEvents = weekQ.slice(0, 12)
        ↓  sync
云函数 applyWeekEvent()：_id = openid|uid|rev|day  ← 主键唯一 = 天然幂等
        stars ∉ [1,3] 拒 / 非今天拒 / stars ≤ 已记拒（delta 0）
        ↓
players.weekStars += delta、weekCleared 按 weekUids 去重 +1
```

- **周键两端口径必须一致**：UTC+8 → ISO 周 `YYYY-Www`（`weekKeyCN` / `weekKeyOf`）；
  `nextResetAt` = 北京时间**下周一 00:00** 的毫秒。测试里把云函数这两个函数抽到 vm 里真跑，
  断言 `2026-W48`、`-W48 → -W49`、`nextResetAt` 落在 GMT+8 周一 00:00。
- **客户端账本只是"本周内本机看到过什么"**，跨设备的累计只有云函数说得准；
  换设备/清缓存后本地值会缺，但下一次 sync 会以云端为准覆盖显示。这是有意的取舍
  （不在客户端存全量历史事件，省存储也省心）。
- **周切换**：`weekLedger()` 发现 `save.weekWeek !== 本周` 就整本清空；云函数 `rollWeek()`
  发现 `weekKey` 不一致就把 `weekStars / weekCleared / weekUids` 归零落库。两边都做，
  谁先醒谁负责。

## 5. 页面结构（`config.RANK`，设计 px）

| 字段 | 值 | 说明 |
|---|---|---|
| `card` | `660×1000`，`cy 812` | 弹窗外框 |
| `title.y / size` | `388 / 40` | 「排行榜」 |
| `info` | `y 446, h 42, size 20` | 信息条（规格写 452/48，会压页签顶边，上移收窄 6px） |
| `tabsY` | `495` | 三页签 |
| `list` | `x 92, w 566, top 584, rowH 68, step 76, rows 7` | 7 行；`h = 532 = 6×76 + 68` |
| `mine` | `y 1140, w 566, h 110` | 我的名次常驻卡 |
| `foot.y / size` | `1252 / 18` | 脚注 |
| `close` | `y 1372, r 38` | 关闭钮（与 v0.49 起的落位一致） |

行内版式：名次 `x0+42`（金/银/铜三色圆，r 21，超过 99 写 `99+`）· 头像 `x0+92` r 22 ·
昵称 `x0+128, y-11, 22px`（`textFit` 截断）· 副信息 `y+15, 18px` · 主值 `★N` 右对齐 `x0+w-24, 24px`。

**我的名次卡三态**：前 7 名 →「已在榜上 · 第 N 名」；榜外 → 「再得 X 星进入前 7」；空榜 →
「还没有人上榜 / 通关一关即可上榜」。好友榜额外显示「好友榜只显示已授权微信好友」。

## 6. 好友榜（开放数据域）

- 独立 JS 环境，**读不到主域 `config.js`** —— 所以 `openDataContext/index.js` 里的
  `L = { w: 566, h: 532, rowH: 68, step: 76, rows: 7 }` 必须与 `config.RANK.list` 逐字段一致；
  `verify_rank_v65` 第 9 节直接对这两个数字做断言，改一边漏另一边会红。
- **只画前 7 行，不再"顶掉第 7 名"**把玩家自己插进去 —— 自己由主域的常驻卡负责，
  跨域插行会让名次和头像对不上。
- 画完 `wx.postMessage({ type:'friendRank', myRank, myStars, topStars, total })` 回主域；
  主域 `applyFriendRankInfo()` **只在好友榜首开时落地**（切走以后迟到的响应丢弃，避免串页签）。
- KV 键升级 `tangram` → **`tangram_v2`**（多了 `stars / weekStars`），
  开放数据域 `keyList: [KEY, KEY_OLD]` 两个键都读，老玩家不会因为没重开过而消失。

## 7. 兼容 / 埋点

- `rank_t0 / rank_t1 / rank_t2` 语义变了（t1 从本周变好友、t2 从好友变本周），
  **老数据不能直接对比**，看板里按 v0.65 切一刀。
- 云函数对旧包完全兼容：老包 sync 不带 `weekEvents`，`weekStars` 就一直是 0（本周榜垫底，
  但全服榜不受影响）；老包请求 `tab 2` 拿到的是本周榜而不是好友榜 —— 旧包的好友榜本来就走开放数据域，
  不读云端返回，所以不会串。
