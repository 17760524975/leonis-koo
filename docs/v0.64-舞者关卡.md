## 3. 反解链路（`tools/dancer/`）

```
ref.png（由 webp 转来，800×458，10 图 2 行 5 列）
  │
  ├─ seg.js      HSV 分色（比 RGB 稳）：17 个色相桶 → 连通域 → 按 2×5 网格聚合成 10 个图案
  ├─ fit.js      每个色块对 5 种板型 × 8 个 45° 角 × 2 个翻面 = 80 个候选，取 IoU 最高
  ├─ prep.js     全局形状指派：硬约束「2 大 / 1 中 / 1 方 / 2 小 / 1 平」，
  │              1050 种组合全枚举取总 IoU 最大 —— 各块独立选最优会出现「三块大三角」的非法解
  ├─ solve3.js   主流程（去压叠 → 边线族对齐 → 剪影 → 整形），输出 dancers_exact.json
  ├─ snapLines.js 边线族对齐：七巧板的边只有 0°/45°/90°/135° 四个方向
  ├─ offset.js   凸多边形等距外扩/内缩（法向偏移求交点）
  ├─ union2.js   并集（打断 → 丢内部段 → 抵消反向段 → 串环）
  ├─ render2.js  卡片预览（10 宫格 / 单幅大图）；renderSil.js 只画剪影看台阶
  └─ overlay.js  把解画回参考图核对（白线贴不贴色块边缘）
```

**关键一步是「边线族对齐」**：拟合本身的误差只有 0.02~0.05 单位，问题是「本该共线的
两条边差了 0.02」。把每条边的法向偏移 `o = n·a` 按 4 个方向族聚类，再对每块板解
2×2 最小二乘求平移 δ —— 每块板只挪 0.005~0.03 单位，姿势肉眼不变，边却严丝合缝。
对齐会让个别板微微压到一起，所以「对齐 ↔ 只允许 0.008~0.04 微调的去压叠」交替 6 轮。

## 4. 避坑：剪影怎么收口（本次的难点）

历史瑕疵（v0.52 龙尾上滑过头 16.7、v0.63 Y 竖干内跳 12.76）本质是同一类：
**本该是一条直线的边上多出一个台阶**。这次的参考图有两个额外难题：

1. **板间白缝 1~3 世界单位**：插画给每块板描了白边。直接求并集，剪影里就留一道深色
   细线（就是「缝」），而且两块板会断成两个闭环。
2. **角接触**：不少图案里两块板只在一个角上相碰，并集会裂成 2~3 环，而关卡轮廓只能
   是一个闭环。

处理办法（`solve3.js`）：

| 步骤 | 做法 | 判据 |
|---|---|---|
| 剪影 | 7 块板**外扩 d 求并集，再内缩到 keep 余量** | d 从 0.032 起往上试到单环；keep 从 1.5 世界单位起试到「剪影简单 + 七块严实落在里面」 |
| 削针 | `killNeedles`：削掉「出去 270、回来 270」的零宽针 | 口宽 / 两边长之和 < 0.15，且口宽 ≤ 14 单位 |
| 填缝 | `fillSlits`：窄口凹缝整段用中点代替 | 口宽 ≤ 3.5 单位、两端都是凹点 |
| 收毛刺 | `smoothShort`：短于 8 单位的边就试删端点 | **每删一个点都重算「七块板是否仍整块落在新轮廓里」，露头 > 2 单位就放弃** |
| 循环 | 上面三步互相会制造新问题（收毛刺会把凹口拉成一条长针），循环到稳定 | `isSimple` + `pieceInside` 双验 |

**两条必须记住的边界**（写在 `solve3.js` 头部，别再走回头路）：

- **keep 不能太小**：焊缝宽度 = 2×keep − 缝宽。keep=0.25 时焊缝为负，缝又露出来，
  屏幕上一道深色细线；keep=1.5 时焊缝 0.5~2 单位，缝真被填实，而板四周只多 1.5 世界
  单位 = 0.2% 幅面（屏上 1px）。**缝比那点余量显眼得多**。
- **削台阶不能用「删点」**：削 6 单位的台阶就要往里切 6 单位，切完板露头，只好把整圈
  轮廓再放大一圈 —— 那才是「板没填满轮廓」的真正来源。必须用 `smoothShort`，它每删
  一点都验算，宁可不削也不把板挤出去。

## 5. 验收口径的一处调整（诚实记录）

`verify_tangram7` / `verify_v050` 原本按章设定「剪影面积 ≈ 板面积和」的容差：
几何 0.2%、字母 0.6%、生肖 1.0%。舞者章的参考图白缝比生肖粗 4~10 倍（1~3 单位 vs
0.25~0.75），把缝填实之后剪影必然比板大 **3.2~7.0%**，覆盖率 92.7~96.4%。

所以第 4 章单列口径：**面积差 < 7.5%、覆盖率 ≥ 92%、溢出 < 2%**，并在三个脚本里写清
理由。这个量级在屏幕上仍是 1~2px 的一圈余量（抬腿最差 7.46%，其余 4~6%），肉眼看不
出；而真正会「看出来」的结构缺陷由 `verify_v064` 的 190 项断言兜住：

- 七块板**全部完整落在剪影内**（用游戏里的 `fitTol = 3` 世界单位判定，直接对应「玩家
  能不能过关」）
- 最短边 ≥ 6 世界单位（0.6% 棋盘宽）
- **无台阶点**：任何拐点都不许是「近共线（<2°）却还留一个点」
- 轮廓不自交、无重复点、无零长边、点 ≥ 9
- 压叠 ≤ 46 单位²（最小板面积的 0.5%，即游戏判定阈值）
- 落在 1000×1000 卡纸内、尺寸 ≥ 380
