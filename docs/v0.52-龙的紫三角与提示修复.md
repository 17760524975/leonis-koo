## 1. 龙的紫三角：从「蓝色平行四边形下方」挪到「左侧」

参考图里那条龙的头是这样接的：**紫色小三角的竖直直角边整条贴在蓝色平行四边形的左侧竖直边上**，
紫三角的尖朝左上，于是龙头就是「一个向左探出的尖」。

旧实现里紫三角挂在平行四边形**下方**（和橙色正方形下边平齐），所以看起来像下巴而不是头。

### 怎么算出来的

不是目测挪一下，是解出来的：平行四边形 `P` 的世界坐标四条边里有两条是竖直的（长 √2u = 135.76），
紫三角 `T5` 的两条腰也正好是 √2u。于是只需让两者完全共边：

```
P 的左竖边： (71.34, 296.35) → (71.34, 432.11)
T5 的直角顶点必须落在左下角，两条腰分别向上、向左
  → ang = 315°, flipped = true, (x, y) = (26.08, 386.86)
```

校验：解出来的三个顶点是 `(71.33,296.35) (-64.43,432.11) (71.33,432.11)`，
与 P 的左上 / 左下偏差 **0.01** 单位（0.007 屏幕像素）—— 整条边严丝合缝。

调整前后对比：紫三角的 x 从 `201~337`（下方）变成 `-64~71`（左侧），
`pieceInside` 仍为 true，面积和仍是 16u²。

### 连带问题：整条龙变成 993 宽，超出卡纸

紫三角往左一探，龙的 bbox 从 857 涨到 **993**，卡纸只有 1000。
第一次改完截图里左右两端都被圆角裁掉了（只剩 3.3 单位 ≈ 2.4px 留边）。

七块板的尺寸是全局固定的（u = 96，所有关卡共用一套托盘），**不能缩放**，只能动**相对位置**。
绿中三角 `T3` 原本贴在红大三角 `T1` 右腰的「下半段」，沿这条 45° 腰往上滑即可：

```
T3 左腰起点 (657,486)  ←→  T1 右腰起点 (605,434)
沿腰方向最多能滑 52 单位（再多就整条悬空）
实测取 72 单位：T3 有一小截（20 单位 = 0.2u）探出 T1 顶点，
                 但仍是共线贴边，剪影只在背上留一个小缺口
结果：993 → 933，留边 24.2px（卡纸 735px 宽）
```

> 为什么不干脆把绿三角转 90°（bbox 直接省 137）？因为它是「尾巴」，
> 参考图里就是「上边水平、尖朝下」的横旗形，转了就不像尾巴了。

## 2. 龙里藏着的一块 4.25% 压叠（顺带修掉的判定 bug）

修完上面两条跑验收时，`convexOverlapArea` 报出 **正方形 `S` 与平行四边形 `P` 重叠 784u²（4.25%）**。
查下去发现两件事：

### 2.1 数据问题

`P` 的右边界在 x = 207.1，`S` 的左边界在 x = 201.2 —— **x 方向压了 6 个单位**。
这是早期拟合留下的，一直存在，只是没人发现（原因见 2.2）。
4.25% 已经超过 `pieceFit` 的「重叠 > 板面积 2% 判压叠」阈值，
意味着**玩家按标准解摆好，判定也认不出「放好了」，这一关会死活过不去**。
修法：`P`（连同贴在它左边的紫三角）整体左移 6，右边界 201.1 正好贴上 `S` 的 201.2。

### 2.2 真正的 bug：`convexOverlapArea` 对翻面的板恒返回 0

七巧板里 `T3`、`P` 在多数关卡里是 `flipped` 的。`G.toWorld()` 的变换是
`p → R(angle) · F(flipped) · p + (x,y)`，**翻面会把多边形的绕向从逆时针翻成顺时针**。
而 `convexOverlapArea` 用的 Sutherland–Hodgman 裁剪里，「内侧」判据是 `side >= 0`，
只对逆时针成立 —— 顺时针时所有点都被判成「外侧」，裁剪结果为空，函数返回 0。

后果：
- 两块**翻面**的板叠在一起，判定完全看不见（`pieceFit` 会放行）；
- 龙的 `P` 与 `S` 压了 6 单位也没人发现；
- v0.51 里我一度以为「面积外扩 -0.06%」是正常现象，其实也是这个 bug 的副作用。

修法（`js/geom.js`）：加一个 `ccw(poly)`，在 `convexOverlapArea` 入口把两个多边形都规范成逆时针。

修完之后：
- `G.convexOverlapArea(poly, poly) === G.area(poly)` 对所有 7 块板成立（自交叠 = 自身面积）；
- 生肖 12 关重新扫出的真实压叠：龙 `T2-T3` 0.06%、蛇 `T1-T3` 0.50%、马 `T2-P` 0.27%、猴 `T2-T3` 0.07%；
- 其余 45 关（几何/字母）没有新增超标项，`verify_v050` 仍是「93 关全部通过」。

`verify_v051` 的压叠阈值从 0.2% 放到 **1%**：判定口径是 2%，1% 以内的重叠是两块板在同一条
接缝上错了半个像素（≈0.07 屏幕像素），既不影响判定也看不出来；超过 2% 才真的会卡住通关。

## 3. 猴：把穿过身体的那条缝合上

用户圈出来的那条竖线在 `T3`（中三角）与 `T2`（大三角）之间。

```
T3 顶部顶点 (494.8, 252.0)
T2 左上顶点 (503.5, 243.4)   ← 这个点同时是正方形 S 的右顶点
两点相距 12.2（沿 S 的右下边），T3 到 T2 的最近距离 8.63
```

也就是说 `T3` 精确地落在 `S` 的边上，但离 `T2` 差了 8.6 —— 栅格膨胀 1 格（0.25 单位）桥接不了，
剪影就在那里凹进去一条 8.6 单位宽的竖缝。

修法：把 `T3` 平移到 `(x+8.7, y-8.6)`，让它的顶部顶点正好落在 `T2` 的左上（= S 的右顶点）。
移动后：

- `T3` 的竖直腰 `x = 503.5` 与 `T2` 的左边完全重合（长 192 vs 271.5，覆盖上半段）；
- `T3` 的斜边与 `T5` 的斜边仍然共线（延长线关系，偏差 0.9 → 0.0）；
- 猴的相邻板间最大缝从 8.63 降到 **0.07**，剪影不再断开。

## 4. 提示系统：不再指向「已经被占满的位置」

### 现象

用户截图：`T1` 的位置上已经摆好了一块大三角，点提示，金色框还是圈在那个位置上，
让你「把同样形状的板再放一遍」。

### 根因

七巧板里 **T1/T2 是同一块大三角、T4/T5 是同一块小三角**，形状完全一样。
v0.50 把判定从「和标准解逐位对齐」改成「整块落位」之后，玩家拿 `T2` 那块去填 `T1` 的位置，
几何上完全正确、判定也认是拼对了 —— 但旧 `pickHintPiece` 是**按 id** 找「哪块还没上板」：

```js
for (i...) { p = pieceOf(lv.solution[i].id); if (!p.onBoard) return st.id; }   // ← 只看 id
```

`pieceOf('T1')` 那块确实还在托盘，于是提示指回 `T1` 的槽位 —— 可那个槽位已经被 `T2` 占了。

### 修法

把「选哪块」从**按 id** 改成**按槽位是否已被占住**：

```js
function slotCovered(st) {                  // 某个标准解槽位是否已被某块板几何重合地占住
  var slotPoly = G.toWorld(LOCAL[st.id], st);
  ... for each onBoard piece: if (convexOverlapArea(piecePoly(q), slotPoly) > area*0.98) return true;
}
function pickHintPiece() {
  var covered = lv.solution.map(slotCovered);          // 先算出哪些坑已经被填了
  // ① 空槽 + 对应那块在托盘 → 圈托盘、指落点
  // ② 空槽 + 对应那块上板但摆歪 → 圈它、指该槽
  // ③ 空槽 + 对应那块已落在别的槽（同形状互换）→ 圈它、指空槽
}
```

配套改两处状态判断（提示的「消失」与「能不能再买」）：

| 位置 | 旧 | 新 |
|---|---|---|
| `useHint` 后每帧的存活判断 | 被圈的那块 `onBoard && pieceFit` 就消失 | 目标**槽位**被填上才消失 |
| `canTakeHint`（防连点扣费） | `pieceSolved(pieceOf(id), st)` | `!slotCovered(st)` |

不这么改的话，在同形状互换的场景下，被圈的那块早就落在别的槽上了，
提示会在下一帧立刻消失 —— 玩家花了道具什么也看不到。

### 验收

新增 `tools/verify_v052.js`（12 项）：

```
[OK] 七块都摆好时，提示返回 null
[OK] T2 占了 T1 的槽位 → slotCovered(T1 槽) = true
[OK] 提示不再指回已被占满的 T1 槽位        hint=T2
[OK] 提示落在唯一还空着的槽位（T2 的槽）    hint=T2
[OK] 小三角互换（T5 占 T4 的位）后提示落在 T5 的槽位
[OK] 空槽 + 托盘有对应块 → 提示那块
[OK] 槽位空着 + 那块摆歪 → 提示它
[OK] 目标槽还空着 → 提示保持显示
[OK] 目标槽被填上 → 提示自动消失
```

顺带把 `pickHint / slotCovered / useHint` 挂到 `_debug`，方便以后直接用测试驱动这块逻辑。

## 5. 评星规则（回答「几星是凭什么定的」）

代码在 `js/core.js` 的 `win()` 里，就地三条，**和提示无关、和连击无关、和失败次数无关**：

```js
var stars = 1;
if (state.elapsed <= lv.parTime * C.STAR.twoStarTimeFactor) stars = 2;   // 1.6 倍
if (state.elapsed <= lv.parTime && state.steps <= lv.parSteps) stars = 3;
```

| 星级 | 条件 |
|---|---|
| ★☆☆ | 拼出来就至少 1 星（通关即得） |
| ★★☆ | 用时 ≤ `parTime × 1.6` |
| ★★★ | 用时 ≤ `parTime` **且** 步数 ≤ `parSteps`（两条同时满足） |

- `elapsed`：本关从开局到通关的秒数（暂停/结算页不计）。
- `steps`：**操作次数**，不是「放对了几块」。每完成一次旋转 +1，每完成一次落板/移动 +1（`js/core.js` 的 `state.steps++`，共 4 处）。
- **用提示不降星**。v0.3 时代确实有过「用过提示本关封顶 ★★」，v0.20 已经取消 ——
  提示收窄成「只指一步」且每次都要付费（查找道具 / 40 巧币 / 看视频），再降星等于「花钱买罚」。

各章的目标值（`js/levels.js`）：

| 章节 | parTime | parSteps |
|---|---|---|
| 几何·入门（1–19） | 80 ~ 130 秒 | 22 ~ 29 步 |
| 字母·A–Z（20–45） | 90 秒 | 18 步 |
| 生肖·十二（46–57） | 90 秒 | 18 步 |

所以生肖关拿三星的口径是：**90 秒内拼完，且总操作不超过 18 次**。
7 块板如果每块都是「一次拖到位、一次都不转」，理论下限是 7 步；
18 步留给翻面、旋转、以及几次放偏重放 —— 正常玩一遍大概是 12~16 步。
