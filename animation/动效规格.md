## 0. 动效基调（先定调，后续版本沿用）

**一句话**：彩色木块落在白卡纸上的手感。

> 基调变化说明：v1.0 深色方案是"爷爷书桌上那盒用了一辈子的木块"，动效关键词是**克制、笃定**，一切幅度压到最小。
> v1.1 亮色方案是"午后三点的晴日玩具台"，关键词变成**明快、好奇、有成就感**（6.5）。这不只是换色 —— **深底靠明暗分物，亮底只能靠投影和层次分物**，所以同一套动效在亮底上必须做得更"实"：投影要参与动画，反馈要更明确。本版规格据此调整了 5 处（详见 §11）。

| 维度 | v1.0 深色方案 | **v1.1 亮色方案（本版）** | 为什么改 |
|---|---|---|---|
| 节奏 | 短 | **短，且更紧凑** | 明快感来自"快"，不来自"弹" |
| 位移幅度 | 2–4px | **4–6px**（+2px） | 亮底上小位移被高对比吃掉，看不出来 |
| 缩放幅度 | 1.04–1.06 | **1.04–1.08** | 同上 |
| 弹性 | 几乎不用 | **几乎不用**（仍是全片仅 1 处轻 back） | 弹性强会掉进"幼稚"，6.5 禁忌 |
| **投影** | 静态装饰 | **参与动画**（随抓取/成局变化） | 亮底环境下，投影是唯一的"高度"语言 |
| 反馈色 | 暖金 `#D9A03C` | **暖黄 `#FFB93D`**（星级/主按钮）+ **白色高亮环**（吸附） | 6.5.1 定了暖黄；吸附改用白环，见 §3 #3 |
| 描边 | 深墨 `#1E1410` | **同色系加深 20%** | 6.5 明确禁止黑描边 |

**三条铁律**

1. **板件的 transform 不交给 CSS transition。** 板在拖拽中每帧被内联 `transform` 改写，CSS transition 会从"当前计算值"反复重启，产生"追上—落后—追上"的抖动。板件的旋转/翻转/脉冲/抓取/成局/投影**一律 rAF 手写**。
2. **绝不动 `width` `height` `top` `left`。** 进度条用 `transform: scaleX()`，面板用 `translateY`，投影用 `ctx.shadowBlur/shadowOffsetY`（绘制属性，不触发 layout）。
3. **同一时刻活动元素 ≤ 10。** 本版最多的一帧是成局（4 板 + 4 投影 + 进度条）共 9 个，安全余量 1。

## 1. 缓动 Token 表（程序建常量，禁止在代码里散写 bezier）

| Token | cubic-bezier | 数学近似 | 用在哪 |
|---|---|---|---|
| `E_ENTRY` | `cubic-bezier(0.22, 1, 0.36, 1)` | easeOutQuint | 旋转（策划指定值）、高亮环起亮 |
| `E_FEEDBACK` | `cubic-bezier(0.25, 0.46, 0.45, 0.94)` | easeOutQuad | 按钮、抓取、进度条、面板淡入、页面转场、关卡格、环扩散 |
| `E_SETTLE` | `cubic-bezier(0.4, 0, 0.6, 1)` | easeInOutQuad | 脉冲回落、成局收缩、环淡出、星级第二段 |
| `E_BREATH` | `cubic-bezier(0.37, 0, 0.63, 1)` | easeInOutSine | 环呼吸、翻转、重叠闪红 |
| `E_POP` | `cubic-bezier(0.33, 1, 0.68, 1)` | easeOutCubic | 星级第一段（0.6→1.15） |
| `E_WIN_BACK` | `cubic-bezier(0.34, 1.2, 0.64, 1)` | 轻度 easeOutBack | **全片唯一回弹**：成局回弹段 |

> 为什么星级不用 `back-out`：星级关键帧 0.6→1.15→1 已把上冲做进数值，再叠 back 曲线会冲到 1.23 以上，接近"幼稚"。见 §11 偏差 3。

## 3. 逐条规格

### #1 按钮 · 按下下沉

| 字段 | 内容 |
|---|---|
| 触发条件 | `pointerdown` 落在按钮热区内（热区 ≥ 88×88，6.4）。视觉可以更小，热区不能 |
| 起始态 | `transform: translateY(0)`；底部厚边 4px（主按钮）/ 3px（次按钮） |
| 结束态 | `transform: translateY(2px)`；底部厚边 2px / 1px |
| 时长 | **80ms** |
| 缓动 | `cubic-bezier(0.25, 0.46, 0.45, 0.94)` |
| 实现方式 | **CSS transition** on `transform`。按钮不参与每帧改写，transition 走合成层最省事 |
| **亮色方案要点** | 6.5.1 给了按钮"底部厚边"（主 `#E08A00` 4px / 次 `#E3E9F2` 3px）。**厚边必须同步变薄**：只上移 2px 而厚边不变，看起来是"整个按钮往上挪"；厚边同时从 4→2px，才是"被按下去压扁了"。厚边用**两个固定档位 class 切换**，不做插值（`border-bottom-width` 插值会触发 layout） |
| 中断与重入 | 新的 `pointerdown` 直接覆盖，从当前位置重定向，不排队。`pointercancel` 视同 `pointerup`。`pointerleave` 也算抬起（手指拖出按钮） |
| 音效对齐点 | `sfx_tap` 在**第 0ms**。200ms 内多次 down 只播一次（防机枪声） |
| 性能注意 | 只改 transform → 不触发 layout。**不加 `will-change`**：5 个工具栏按钮常驻 will-change 会白占合成层内存，而 80ms 的 transition 本身就够轻 |

### #2 按钮 · 抬起回弹

| 字段 | 内容 |
|---|---|
| 触发条件 | `pointerup` / `pointercancel` / `pointerleave` |
| 起始态 | `translateY(2px)` |
| 结束态 | `translateY(0)` |
| 时长 | **120ms** |
| 缓动 | `cubic-bezier(0.25, 0.46, 0.45, 0.94)` |
| 实现方式 | CSS transition（同 #1） |
| **不做的两件事** | ① **不加 ease-out-back 回弹** —— 7.5 #2 定的是 `ease-out`，且带 overshoot 会掉进"幼稚"。② **抬起不配音**，否则连点会有 2 倍音密度 |
| 中断与重入 | 抬起过程中再次按下 → 从当前位置转向 +2px，80ms |
| 合计手感 | 80 + 120 = **200ms**，正好卡在"不肉"的边界（硬指标 ≤200ms） |

> **冷启动对齐**：`pointerdown` 到视觉开始动的延迟必须 ≤ 1 帧（16ms）。若程序在 `pointerdown` 里先跑几何判定再上 class，请加一帧 `requestAnimationFrame` 再上 class，避开某些机型首帧丢样式。

### #3 板件 · 吸附命中脉冲 + 白色外高亮环

> **本节是亮色方案改动最大的一项。** v1.0 是"描边改暖金加粗"，在 `#FFFFFF` 白卡上完全失效 —— 白色底上加亮描边＝看不见。改为**白色外高亮环向外扩散后淡出**。

| 字段 | 内容 |
|---|---|
| 触发条件 | 松手后几何判定返回 `snapSuccess === true`（第 1 层顶点吸附命中，距离 < 22px@1000 坐标系） |
| **A. 板身脉冲** | |
| 起始态 | `scale = 1.00` |
| 结束态 | `scale = 1.00`（回位） |
| 关键帧 | `t=0` 1.00 → `t=70ms` **1.06** → `t=140ms` 1.00 |
| 时长 | **140ms**（上升 70 + 回落 70） |
| 缓动 | 上升 `cubic-bezier(0.22,1,0.36,1)`；回落 `cubic-bezier(0.4,0,0.6,1)` |
| **B. 高亮环（双层）** | |
| 环的几何 | 沿板的**外轮廓等距外扩**画描边。**必须做真正的等距偏移（每条边沿法线平移 d，角点取相邻偏移线交点，锐角处斜接限位 2.5d），不能用一个 `scale()` 近似** —— 这四块板极扁（3u×1u），等比缩放 1.02 时短轴只外扩 ≈1.6px，环会变成"上下几乎没有"，只剩左右两条线 |
| 环的层级 | **`#1 同色系柔光` 在下，`#2 白色主环` 在上，两者都在板下方。** 白色主环会把柔光的中段盖住，只露出柔光向外散开的部分 |
| **#1 同色系柔光（亮底显影层）** | 描边色 = 该板自己的描边色（A `#D96A3D` / B `#3585BC` / C `#46A66D` / D `#8455CC`）；宽 = `ringW + 7`；α = `ringAlpha × 0.42`；**`filter: blur(2.6px)`** |
| **#2 白色主环** | 描边色 `#FFFFFF`；宽 = `ringW`；α = `ringAlpha`；无 blur |
| 环偏移 `ringOff` | `0px → 4px`（从贴板边扩到板外 4px） |
| 环宽 `ringW` | `4px → 3px`（扩散同时收细，才有"推出去"的速度感） |
| 环透明度 `ringAlpha` | `0 → 0.95`（0–40ms，`E_ENTRY`）→ `0`（40–180ms，`E_SETTLE`） |
| 时长 | **180ms** |
| 缓动 | 偏移 `E_FEEDBACK`；宽度 `linear`；透明度见上 |
| **C. 为什么一定要有柔光层** | **纯白环画在纯白卡上等于没画。** 我做过对照：只画白环时，在 `#FFFFFF` 卡纸上完全不可见（只有压到板下方那圈 `rgba(44,58,75,.14)` 投影的地方才有一点点变化，而且只在下方，读起来像"环只出现在底边"）。加一层同色柔光后，白环有了边界，扩散动作才被看见。柔光不是"发光特效"，它是**白环的显影衬底** —— 这也是它必须用板自己的颜色、而不是随便一个亮色的原因 |
| 实现方式 | **rAF**。板的 transform 每帧被拖拽改写，且环是绘制层不是 CSS 层 |
| 中断与重入 | 见 §4 矩阵 I6 / I7 / I16。要点：**脉冲可被打断**；**高亮环是一次性事件，播完即消失**，不留"已对齐"的持久状态（v1.0 的持久金色描边在亮底上做不到，改为由 #4 的呼吸环承担"未松手的预备态"） |
| 音效对齐点 | `sfx_snap` 在**第 0ms** 起音。视觉峰在 70ms，音的起音先到、视觉紧随，符合"木块落位先闻其声"的物理直觉 |
| 震动 | `wx.vibrateShort({type:'light'})`（浏览器 `navigator.vibrate(8)`）在**第 0ms**。系统短震实际时长不可控，不要依赖它做 8ms 精确对齐 |
| 性能注意 | 重绘单块板 + 一个环，无 layout。4 块板同时吸附的极端情况单帧仍 < 2ms |

### #4 板件 · 吸附半径内高亮环呼吸

| 字段 | 内容 |
|---|---|
| 触发条件 | **拖动中**，板任一顶点与某个吸附目标的距离 < 吸附半径（22px），**且尚未松手** |
| 起始态 | 环 α 0（不可见）；环偏移固定 `3px`；环宽 `3px` |
| 结束态 | 循环，不结束。环 α `0.15 → 0.75 → 0.15` |
| 层结构 | **与 #3 相同的两层**（白色主环 + 同色系柔光 `宽+7 / α×0.42 / blur 2.6px`），两层 α 一起呼吸。这样"预备态"和"命中态"是同一套视觉，只是强度不同，玩家不用重新认 |
| 时长 | **600ms 一循环**，无限循环直到离开半径或松手 |
| 缓动 | `alpha = 0.15 + 0.60 * (0.5 - 0.5*cos(2π·t/600))`，等价 `cubic-bezier(0.37,0,0.63,1)` 的 easeInOutSine |
| **不扩散** | 呼吸态环偏移**固定 3px，不做外扩**。扩散是"事件"，呼吸是"状态"；如果呼吸也扩散，玩家会以为吸附在不断发生 |
| 实现方式 | **rAF**，且在拖拽的同一主循环里用 `cos` 直接算 alpha。**不要为它单开一个动画循环** —— 拖动中已经有 60fps 心跳了 |
| 视觉细节 | alpha 下限 **0.15** 不是 0。到 0 就成了"闪"，7.5 明确要"呼吸，不要闪烁"。上限 0.75 不到 1，给 #3 的 0.95 留出区分度（呼吸＝预备，0.95＝命中） |
| 渲染顺序 | 同 #3：投影 → 环 → 板 |
| 中断与重入 | 见 I8 / I9。**命中吸附时从当前呼吸 alpha 连续过渡到 #3 的 0.95 并继续外扩**，不要先归零再起亮（会闪一下） |
| 音效对齐点 | **无**。呼吸是"预备信号"，声音留给真正的"咔"。这里给声音会让玩家误以为已经吸附成功 |
| 性能注意 | 每帧改环的 alpha 重绘一层。设了呼吸的板最多 1 块（只有一个手指在拖），开销可忽略 |

### #5 板件 · 旋转 45°

| 字段 | 内容 |
|---|---|
| 触发条件 | 点 `↺` / `↻`，且当前有选中板。无选中时按钮置灰（底 `#F4F6F9`、图标 `#C3CDD9`）且不播任何动画 |
| 起始态 | `rotation = 当前视觉角度 rotVis` |
| 结束态 | `rotation = logicalAngle ± 45`，范围 0–315，共 8 档 |
| 时长 | **120ms**（单次转 45°） |
| 缓动 | `cubic-bezier(0.22, 1, 0.36, 1)`（5.3 指定，easeOutQuint） |
| 实现方式 | **rAF**。必须绕**板质心**旋转，不是屏幕中心：顶点在加载时已平移到质心系，`ctx.translate(cx,cy); ctx.rotate(rad); ctx.translate(-cx,-cy)` 或等价矩阵 |
| **关键实现约束** | **`logicalAngle` 与 `rotVis` 必须是两个独立变量。** `logicalAngle` 在点击的**同一帧**就 ±45（不等动画），`rotVis` 去追它。这样连点 8 次逻辑角度精确回到 0，验收 12.3「旋转连点 8 次回到原角度、形状无畸变」必然成立 |
| 亮色方案附注（投影） | 旋转时**投影的偏移方向必须保持朝下**（光源固定在画面正上方），但投影的**形状**要跟着板一起转。Canvas 的 `shadowOffsetX/Y` 按规范**不受当前变换矩阵影响**，所以只要在"已旋转的坐标系里画板"就能自动满足这一点，**不需要额外的 save/restore 技巧**。真正的坑是 `shadowBlur` 的开销：blur 22 单块约 0.5–1.2ms，四块同开 2–5ms。所以成局时必须把 blur 降下来（见 #10） |
| 中断与重入 | 见 I1 / I2 / I5。核心：**追赶式重定向，不排队、不忽略**。完整算法见下方「#5 补充」 |
| 音效对齐点 | **v0.1 不配音效**。8 节清单只有 4 个音效，没有旋转音，程序**不要自行补**（建议 v0.2 加 60ms 极轻木片摩擦，本版不做） |
| 性能注意 | 8 角度 × 2 翻转 = 16 种状态**不预渲染成图片**（7.1 已定程序绘制）。`ctx.rotate` 代价远低于切换预渲染位图 |

#### #5 补充 · 追赶式重定向的完整算法（连点）

> 策划 v1.2 已修订 5.3。**核心硬约束：任意时刻 `|rotVis − logicalAngle|` 不得超过 90°。** 以下是可直接照抄的实现规则。

```
rotateStep(piece, dir):                    // dir = +1 顺时针 / -1 逆时针
  1. piece.logicalAngle = (piece.logicalAngle + dir * 45 + 360) % 360    // 当帧生效，不等动画
  2. dev = shortestDelta(piece.logicalAngle, piece.rotVis)               // 归一化到 -180..180
  3. if |dev| > 90:                                                      // 硬不变量，安全网
       piece.rotVis = piece.logicalAngle - sign(dev) * 90                // 0ms 钳位，无额外动画
       dev = shortestDelta(piece.logicalAngle, piece.rotVis)
  4. T = clamp(60, 120, |dev| / 45 * 120)                                // 时长按偏差距离压缩
  5. tween(piece, 'rotVis', piece.rotVis + dev, T, E_ENTRY)              // 从当前视觉值起，重定向
```

`shortestDelta(a, b)` = `((a - b) % 360 + 540) % 360 - 180`

**规则解读（这四条是给程序的，别自己另发明一套）**

| 规则 | 说明 |
|---|---|
| 逻辑角当帧生效 | `logicalAngle` 在 `pointerdown` 的同一帧就改完。**它代表玩家的真实意图，不接受任何动画延迟**。这样连点 8 次必然回到 0°，验收 12.3 天然成立 |
| 时长按距离压缩 | `dev` 45° → 120ms（正常速 375°/s）；`dev` 90° → 时长封顶 120ms（实际 750°/s，**2 倍速追赶**）。距离越大越快，这就是策划要的"缩短单次时长" |
| 下限 60ms | 避免 `dev` 极小时出现"闪一下"的碎动画。60ms 已经是可感知的下限 |
| 硬钳位 90° | **正常情况下永不触发**，是给实现漂移兜底的。见下方实测 |

**实测数据（我的 demo 用上面这套规则跑出来的，程序实装后可对照）**

| 连点间隔 | 8 次连点后 `logicalAngle` | 最大瞬时偏差 | 钳位触发次数 |
|---|---|---|---|
| 100ms（约 10 次/秒，人手最快） | 0° ✔ | 29.1° | 0 |
| 70ms | 0° ✔ | 29.5° | 0 |
| 50ms | 0° ✔ | 31.2° | 0 |
| 30ms | 0° ✔ | 38.2° | 0 |
| 20ms（50 次/秒，人类做不到） | 0° ✔ | 48.7° | 0 |

**结论**：人手的连点上限大约 10 次/秒，实测最大偏差 **29–49°**，离 90° 上限有充足余量，硬钳位永远不会被触发。**如果程序实装后实测偏差超过 60°，说明缓动没用 `E_ENTRY`（easeOutQuint 极致前置，前 20% 的时间就吃掉 67% 的距离），或者时长压缩被改回了固定 120ms —— 先去查这两处，不要先去调 90° 这个数。**

**注意**：钳位时**不要播放任何额外动画**（不要抖动、不要警示色）。它只是把视觉拉回合法区间，玩家不该感知到"出错"。

#### #6 补充 · D 板凹口标记的定位算法（精确到步长与兜底）

> 7.1 只规定了"凹口内侧 45° 短虚线，长 14 宽 2，白色 α 80%"，没给坐标。**这个不能靠手填坐标** —— 我第一版手填 `(60,-20)` 就落在多边形外，白线画在白卡上等于没画。下面是可以直接实现的搜索算法，**只在板件加载时算一次**（翻转/旋转只改 transform，不改这条线的局部坐标，所以运行时零开销）。

**所有坐标都在「质心系、u 单位」下计算**（即 5.1 的顶点减去质心，未乘 PPU）。D 板质心 = `(5.0227, 0.5682)` u。

```
findNotchMarker(polygon, centroid):        // polygon = 质心系顶点数组（u）

  1. 找反射顶点 V（内角 > 180° 的那个）：
       对每个顶点，cross = (V-A) × (B-V)
       polySign = sign(有向面积)
       反射顶点 = cross * polySign < 0 的那个顶点
       → D 板命中 index 4，V = (0.7273, -0.3182) u

  2. 内角平分线方向（指向凹口内侧）：
       uHat = normalize(A - V)
       wHat = normalize(B - V)
       bis  = normalize( -(uHat + wHat) )        // 反射顶点要取负号
       → D 板：uHat = (0.7071, -0.7071)，wHat = (0.7071, 0.7071)
         bis = (-1, 0)   // 正好指向 -x，因为 D 板的凹口是对称的

  3. 沿 bis 从 t = 4px 到 t = 24px，步长 1px（共 21 次迭代），取第一个满足下面
     「双端点包含」的 t：
       P = V + bis * (t / PPU)
       检测线段长度先用 18px（= 14 目标长 + 两端各 2px 安全边），
       即 half = 9 / PPU，两个方向都试：
         dirA = ( 0.7071,  0.7071)
         dirB = ( 0.7071, -0.7071)
       对每个 dir：
         e1 = P + dir*half,  e2 = P - dir*half
         通过条件 = pointInPolygon(e1) && pointInPolygon(e2) && pointInPolygon(P)
       任一 dir 通过即接受（记下用的是哪个 dir）

  4. 用命中的 t 和 dir 画线，长度回到规格的 14px：
       half14 = 7 / PPU
       A' = P - dir*half14,  B' = P + dir*half14

  5. 兜底（4–24px 全部失败时，理论上不会发生）：
       P = V + bis * (8 / PPU)          // 退到 8px
       线长降到 6px（half = 3/PPU），α 降到 60%
       并把该板标记为 notchFallback = true，方便真机上查
```

**D 板的期望输出（程序可拿去做单测）**

| 量 | u 单位（质心系） | px @ PPU=74 |
|---|---|---|
| 反射顶点 V | `(0.7273, -0.3182)` | `(53.82, -23.55)` |
| 平分线方向 bis | `(-1, 0)` | — |
| 命中 `t` | 4px（第一个候选即通过） | 4 |
| 线段中心 P | `(0.6732, -0.3182)` | `(49.82, -23.55)` |
| 端点 A′ | `(0.6063, -0.3851)` | `(44.87, -28.50)` |
| 端点 B′ | `(0.7401, -0.2513)` | `(54.77, -18.60)` |
| 方向 dir | `(0.7071, 0.7071)`（"\" 这一道） | — |
| 实测线长 | 14.00px ✔ | 14.00 |

**三条实现注意**

1. **`rotVis` 不要归一化，`logicalAngle` 要归一化，两者的差必须走 `shortestDelta`。**
   实测：连点 8 次后 demo 里是 `logicalAngle = 0°`、`rotVis = 360°` —— 视觉上是同一个角度，但如果程序直接写 `if (|rotVis − logicalAngle| > 90)` 就会算出 **360° 的偏差**，触发钳位，板会凭空多转一圈。
   **正确写法**：`dev = ((logical − rotVis) % 360 + 540) % 360 - 180`，永远先归一化再比。
   为什么 `rotVis` 不归一化：它代表"视觉累计转过的角度"，归一化会在 0/360 边界产生一次瞬时跳变，玩家能看见。
2. **`pointInPolygon` 用射线法（奇偶规则）就够**，不需要处理边界退化。但要注意 `t = 4` 时 P 距离凹顶点只有 4px，**别用"到顶点距离 < 2px 就跳过"这种过滤**，会把合法解筛掉。
3. **两个对角方向都要试**。D 板用 `(0.7071, 0.7071)` 通过，但若程序把顶点顺序反了、或以后换板形，另一个方向可能才是合法解。取第一个通过的方向即可。
4. **标记跟随 `scaleX` 一起镜像，不要做反向补偿**（5.4 已要求）。它必须看起来"跟着板翻过去"，这样玩家才能靠它分辨翻转是否发生。

### #7 板件 · 抓取上浮（**投影必须同步加深**）

> 亮色方案下，"浮起来"这件事**不再由描边承担，而是全压在投影上**。深色方案里上浮 4px + 放大 1.04 就够，因为浅色板在深底上会自然"跳出来"；亮色方案里板身本身是高明度，上浮的视觉线索只有投影差。所以这一项的投影参数和位移参数同等重要。

| 字段 | 内容 |
|---|---|
| 触发条件 | `pointerdown` 命中某块板（点在多边形内判定通过） |
| 起始态 | `translateY = 0`；`scale = 1.00`；投影 `offsetY 2 / blur 6 / alpha 0.14 / 无扩散` |
| 结束态 | `translateY = −4px`（**亮色方案从 −4 提到 −6px**，见下）；`scale = 1.04`；投影 `offsetY 10 / blur 22 / alpha 0.24 / spread 0` |
| 时长 | **100ms** |
| 缓动 | `cubic-bezier(0.25, 0.46, 0.45, 0.94)` |
| 投影插值表 | `offsetY: 2 → 10`、`blur: 6 → 22`、`alpha: 0.14 → 0.24`、`offsetX: 0 → 0`（光源固定在正上方，**抓取时不要横向偏移**，否则像板在侧滑） |
| **位移/缩放的亮色调整** | 上浮由 **4px → 6px**，放大 **1.04 → 1.05**。理由：`#F6E9D4` 浅木底 + `#FFFFFF` 白卡 + 高明度彩色板件的组合下，4px 的位移差被压得很小，读不出来。6px 仍是"轻拿"，不会变成"甩出去" |
| 实现方式 | **rAF**，与拖拽位移**并行的两条独立通道** |
| **关键约束** | **绝不为播这 100ms 动画而延迟跟手。** 手指一动，板位置必须当帧跟上（位移通道 0 延迟）；上浮、放大、投影加深是叠加在位置上的"表现层"，100ms 内走完。若做成"先播完抓取再跟手"，玩家会觉得板粘手 |
| 中断与重入 | 100ms 内松手 → 反向 100ms 回位（`E_FEEDBACK`，投影同步退回）。若松手后吸附成功 → 直接转 #3，`scale` 从当前值（如 1.03）继续向 1.06 走、投影**保持抓取档再 180ms 退回常态**，**不要从 1.0 和常态投影重置**（会闪一下） |
| 音效对齐点 | `sfx_pick`（80ms 木头轻拿起"嗒"）在**第 0ms**，与 `pointerdown` 同帧。延迟超过 16ms 就感觉"声音和动作分离" |
| 性能注意 | `ctx.shadowBlur` 在部分低端安卓上较贵（每帧要对整个路径做高斯）。**单块板 + blur 22 的实测开销约 0.5–1.2ms**，4 块同时开着也只有 2–5ms，在 8ms 单帧预算内。但**成局时必须把 blur 降下来**（见 #10），否则 4 块板 blur 22 同时开就是 5ms+ |

|---|---|
| 触发条件 | `pointerup` 后判定完成，覆盖率与上一次显示值不同 |
| 起始态 | 填充 = 旧值；数字 = 旧值 |
| 结束态 | 填充 = 新值；数字 = 新值 |
| 时长 | **300ms** |
| 缓动 | `cubic-bezier(0.25, 0.46, 0.45, 0.94)` |
| 样式（6.5.1） | 轨道 `#E8EEF7`，填充渐变 `#63C88B → #4FB87A`（横向 90deg），高 14，圆角 999 |
| 实现方式 | **rAF，条与数字同一 tick 驱动**（不要一个用 CSS 一个用 JS，两者会错开 1–3 帧，肉眼能看出"数字跑在条前面"） |

| **性能红线** | **绝对不要用 `width` 做过渡。** 702px 宽的条每帧改 width 会触发 layout + paint，低端安卓实测掉到 30fps。`scaleX` 只走合成层 |
| 数字 | `font-variant-numeric: tabular-nums`，否则滚动时字宽跳变、数字左右抖。取整显示 `Math.round`，**不要显示小数** |
| 中断与重入 | 见 I15：**重定向**，从当前显示值向新值重新计 300ms，不排队。连续拖拽时排队会让进度条滞后于真实值 |
| 音效对齐点 | **无**。给声音会让"覆盖率上升"显得吵，破坏专注 |
| 曲线选择说明 | 单块板贡献 8%–25%（3.2）。跨 10% 以上的跳变不要中途减速，匀一点更"有分量"，所以用 `E_FEEDBACK` 而不是 quint |

### #10 全部板件 · 成局收缩（**含投影降档**）

| 字段 | 内容 |
|---|---|
| 触发条件 | 判定通过：覆盖率 ≥99% 且 溢出 <1% 且 无重叠（3.3 三条同时满足） |
| 起始态 | 每块板顶点在真实位置；投影为常态档 |
| 结束态 | 顶点回原位；投影**降到拼合档**（见下） |
| 关键帧 | `t=0` 原位置 → `t=130ms` 每顶点向**该板自身质心**内缩 **2px** → `t=260ms` 回原位 |
| 时长 | **260ms** |
| 缓动 | 内缩 `cubic-bezier(0.4,0,0.6,1)`；回弹 `cubic-bezier(0.34,1.2,0.64,1)`（**全片唯一一处 back**，×1.2 极轻） |
| 实现方式 | **rAF**。程序为每块板维护两份顶点缓存 `vertsNormal` 与 `vertsShrunk`（每顶点向质心移动 2px），插值。**不要用 scale 近似** —— B 板宽 44px 缩 2px = 0.955，A 板宽 132px 缩 2px = 0.985，用统一 scale 会让小三角缩过头、大梯形几乎不动 |
| **★ 投影降档（亮色方案特有，必须做）** | 4 块板拼合完成时彼此是**贴边**的。若各自还开常态投影 `offsetY 2 / blur 6 / α .14`，相邻板的投影会在**每条接缝处叠成一道深色线**，整个拼好的图形看上去像被格子切碎了。规定：**从判定通过起 260ms 内，4 块板的投影同步 fade 到 `offsetY 1 / blur 3 / alpha 0.06`**，接缝保持干净。回弹段结束后停在新档，直到玩家再次拖走任一块板才逐块恢复常态 |
| **★ 投影不叠成一团的验证方法** | 4 块板全部内缩 2px 后，相邻边各退 2px → 接缝张开 4px。投影 blur 3 在 4px 的缝里不会互相咬合。**若发现接缝仍有深色线，说明 blur 没降下来，去查 `ctx.shadowBlur` 有没有在 restore 后漏恢复** |
| 与结算的时序 | 成局 260ms 结束 → **空窗 400ms**（让"拼成了"这个瞬间停住）→ 结算面板 200ms 淡入。判定通过到面板可读共 **660ms** |
| 中断与重入 | 见 I10 / I11：`0–260ms` 全屏输入锁定；`260–660ms` 允许"点屏幕催出面板"（淡入缩短 80ms），但所有按钮继续禁用 |
| 音效对齐点 | `sfx_win`（1.2s，上行三音）在**第 0ms**。它覆盖 260ms 成局 + 400ms 空窗 + 200ms 面板淡入 + 星级前 340ms = 1200ms，正好托住整个结算链路。**不要让程序在面板出现时再播一次 win 音** |
| 性能注意 | 4 板 + 4 投影 + 进度条 = 9 个元素同帧变动。**投影降档本身也是性能措施**：blur 从 6 降到 3 让这一段的绘制开销反而变小 |

### #11 结算面板 · 淡入上移

| 字段 | 内容 |
|---|---|
| 触发条件 | 成局动画结束（260ms）+ 延迟 400ms = **判定通过后 660ms** |
| 起始态 | 面板 `opacity: 0`，`translateY(+24px)`；遮罩 `opacity: 0` |
| 结束态 | 面板 `opacity: 1`，`translateY(0)`；遮罩 `opacity: 1`（遮罩层本身用 `rgba(44,58,75,.28)`） |
| 时长 | **200ms**（面板与遮罩同时长、同时起） |

## 4. 中断与重入矩阵（策划文档没写全，本表补齐）

> 这是本版规格里**最需要程序逐条对照实现**的部分。默认行为"播完再响应"对本作不合适：120ms 的旋转、140ms 的脉冲相比人的操作节奏太短，玩家一定会撞上。

| ID | 冲突场景 | 处理规则 | 依据 / 理由 |
|---|---|---|---|
| **I1** | 旋转动画中，用户又点旋转（连点） | **追赶式重定向**。`logicalAngle` 当帧 ±45（不等动画）；`rotVis` 从当前视觉值向新目标插值，时长按偏差压缩 `T = clamp(60,120,|dev|/45×120)`，**不排队、不丢输入**。硬不变量：`|rotVis − logicalAngle| ≤ 90°`（超限则 0ms 钳位）。完整算法见 §3「#5 补充」，含实测偏差表 | 验收 12.3 要求"连点 8 次回到原角度"。若照 5.3 字面"忽略新输入"，人连点间隔常在 120–250ms，会有 30–50% 点击被吞，按钮像失灵。**策划 v1.2 已修订 5.3 采纳本方案，并追加 90° 硬约束** |
| **I2** | 旋转动画中，用户按住板开始拖 | **立即终止旋转**：`rotVis` 在 0ms 内落到 `logicalAngle`（可能跳 1–45°），同步启动 #7 抓取（100ms）。位置立刻跟手 | 5.3 明确"允许拖拽打断…立即结束并落到目标角度"。跳变被抓取的 100ms 缩放+投影加深掩盖 |
| **I3** | 翻转动画中，用户点旋转 | **允许并行，不互斥**。`rotation` 与 `scaleX` 是正交分量 | 强行互斥会让"转+翻"连招变迟钝。翻到薄片时旋转是翻牌的自然视觉，不违和 |
| **I4** | 翻转动画中，用户拖拽 | 同 I2：`flipVis` 0ms 落到目标值，启动 #7 | 一致性 |
| **I5** | 翻转动画中，用户再点翻转（连点） | `flipped` 立即取反，`flipVis` 从当前值向新目标插值，时长 `clamp(60,180,|ΔflipVis|/2×180)`。连点 2 次回原形 | 与 I1 同一原则，避免按钮失灵 |
| **I6** | 吸附脉冲/白环播放中，用户又拖走该板 | 脉冲 `scale` **立即归 1** 并转 #7（1→1.05，100ms）；**白环不打断，让它把 180ms 播完**（它已是最外层叠加，不参与缩放）；`sfx_snap` 不重播 | 脉冲是"确认信号"，声已入耳；继续播会和抓取缩放打架。但白环是独立的扩散层，打断它反而会看到"半圈环突然消失" |
| **I7** | 吸附脉冲播放中，用户点旋转 | **并行**：scale 脉冲 + rotation 各自独立。白环照常播 | 正交分量 |
| **I8** | 呼吸环循环中，命中吸附 | 呼吸**立即停止**，环 α 从当前值**连续过渡**到 #3 的 0.95 并开始外扩（不归零重启） | 连续过渡避免"闪一下" |
| **I9** | 呼吸环循环中，板离开吸附半径 | 80ms 内环 α 回 0（`E_FEEDBACK`） | 短，不留残影 |
| **I10** | 成局动画（260ms）中，用户点返回 | **全屏输入锁定 0–260ms**（含返回按钮 `pointer-events:none`） | 260ms 很短，打断会破坏"拼成了"的唯一高光时刻 |
| **I11** | 成局后 400ms 空窗中，用户点任何地方 | 所有按钮继续禁用；但**点屏幕任意处 → 跳过等待**，面板立即出现（淡入 200→80ms） | 玩家等不及可以催，但不会误退拿到空白结算 |
| **I12** | 结算面板淡入（200ms）中，用户点背景 | **忽略**。遮罩 `pointer-events:none` 直到淡入完成；面板按钮在淡入完成 **+80ms** 后启用 | 防"幽灵点击"——玩家手还停在成局时点过的位置 |
| **I13** | 星级点亮（360ms）中，用户点"下一关" | 置灰禁用，播完才启用 | 星级是本版唯一成绩展示，跳过 = 不给看 |
| **I14** | 页面淡入（200ms）中，用户再点导航 | **忽略**。导航按钮 `pointer-events:none` 200ms，**不排队** | 转场不可重入；排队会造成"点了没反应然后突然连跳两页" |
| **I15** | 进度条滚动（300ms）中，覆盖率又变 | **重定向**：从当前显示值向新值重新计 300ms，不排队 | 连续拖拽时排队会让进度条滞后真实值，玩家看到"放好了但条还是旧的" |
| **I16** | 同一块板 200ms 内连续两次吸附命中 | 第二次脉冲从当前 `scale` 起播（可能是 1.03），不从 1.0 重置；`sfx_snap` 200ms 内只播一次 | 避免连响；视觉连续 |
| **I17** | 重叠闪红（400ms）中，用户继续操作 | **不打断**（5.6 "不阻止继续操作"）。闪红是叠加层，不抢输入。400ms 内再次判定出重叠 → 重新起播 | 闪红是信息，不是模态 |
| **I18** | 慢放 0.25x 下发生上述任一冲突 | 所有**逻辑判定阈值不变**，只有时间轴 ×4（追赶速率也 ×4） | 慢放只拉时间轴，不改规则。这条保证 demo 的审查结论能直接搬到真机 |

## 6. 性能与实现归属（哪些能用 CSS、哪些必须 rAF）

| 元素 | CSS transition/animation | 必须 rAF | 理由 |
|---|---|---|---|
| 按钮 #1 #2 | ✅ | | 独立元素，不被每帧改写 |
| 板件 #3 #5 #6 #7 #10 | | ✅ | 板位置拖拽中每帧变，CSS transition 的 transform 会和拖拽内联 transform 互相覆盖 → "追上—落后—追上"抖动 |
| 高亮环 #3 #4 | | ✅ | 环是 Canvas 绘制层，不是 DOM |
| 投影 #7 #10 | | ✅ | `ctx.shadow*` 是绘制属性 |
| 进度条 #8 | | ✅ | 条与数字必须同一 tick；Canvas 版天然逐帧 |
| 面板 #11 | ✅ | | 不参与每帧交互 |
| 星级 #12 | ✅ animation | Canvas 版用 rAF | 独立元素 |
| 页面 #13 | ✅ transition | Canvas 版用 rAF | |
| 关卡格 #14 | ✅ animation + delay | Canvas 版用 rAF | |

**会掉帧的三个坑（务必避开）**

1. **进度条用 `width` 过渡** → 每帧 layout，低端安卓掉到 30fps。改 `transform: scaleX()`。
2. **`ctx.shadowBlur` 和 `ctx.rotate` 混用** → 若在旋转后的坐标系里画板，投影会跟着转（光源不固定）。必须 `save()` 在未旋转坐标系画投影 → `restore()` → 再画旋转后的板身。
3. **成局时 4 块板同时开 blur 22** → 5ms+ 绘制。成局必须把投影降到 blur 3（这既是视觉需求也是性能需求）。

## 7. 与程序的协作说明（交给韦码农）

**必须由程序写代码实现的**：#3 #4 #5 #6 #7 #8 #9 #10（8 项，rAF 手写）。这 8 项都是板件的绘制层属性，Canvas 里没有对应的 CSS。

**可以直接用 CSS 过渡的**：#1 #2 #11 #13 #14（5 项）+ #12（CSS animation）。这些是独立 DOM/固定位置元素。

**装 CSS 里的那一项**：#8 的进度条数字如果程序在 Canvas 里画，就全走 rAF，不用 CSS。

**建议程序建的结构（伪码，不是实现代码）**

```
每块板的运行时状态（都是数字，便于插值）：
  logicalAngle  // 0/45/…/315，点击即改
  rotVis        // 视觉角度，追 logicalAngle
  flipped       // bool
  flipVis       // 1 → -1
  scaleVis      // 1 / 1.05(抓取) / 1.06(脉冲峰值)
  liftY         // 0 / -6(抓取)
  shadowBlur, shadowAlpha, shadowOffsetY   // 投影三参数
  ringOffset, ringWidth, ringAlpha         // 白环三参数
  shrinkT       // 0..1，成局内缩进度
```

一个统一的 `pieceAnimTick(dt)` 把这些全部推进，然后一次 `drawPiece()`。**不要给每个属性单开定时器**。

**统一时间轴**：建议程序做一个全局 `timeScale`（默认 1），所有 `dt` 乘它。这样真机上做慢放调试、以及 demo 的 0.25x 审查都走同一条路径。
