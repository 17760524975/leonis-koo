## 0. 动效基调（v1.1 亮色方案延续，本版专项细化）

**一句话**：拼好的那一瞬，图案中央"砰"地开出一束七色花，然后温柔地把舞台交给结算面板。

| 维度 | 取值 | 理由 |
|---|---|---|
| 节奏 | 前段极快（绽放 280ms），后段缓（淡出 340ms） | "成就感"来自绽放的爆发力，退场要柔，不能抢结算 |
| 弹性 | 全片仅 1 处轻 `easeOutBack`（绽放 scale 名义终点 1.08，过冲视觉峰值 ≈1.14） | 延续 v1.1"几乎不用弹性"铁律，overshoot 只给主花一下，不做抖动；1.14 仍低于"幼稚"阈值 1.2 |
| 位移 | 卫星花向外弹开 170px 级（大位移，但只此一处） | 这是本作唯一允许的大位移，因为是"庆祝"而非"交互反馈" |
| 投影 | 花瓣不加 shadow（低端机 blur 贵），用双色描边近似层次 | 亮底要层次，但动效只在 1 秒内，性价比低，改用半透明叠色 |
| 素材 | **零图片**，全部 Canvas 路径绘制 | 遵守 §2.3 自包含 + A4a 边界 |

**三条铁律（继承 v0.1，本版仍生效）**
1. 只用 `transform`（translate/scale/rotate）+ `globalAlpha` + Canvas 路径，**绝不改 DOM 尺寸属性**（小游戏端本就无 DOM）。
2. 同一帧活动元素 ≤ 10 个逻辑对象 → 本片是 1 主花 + 6 卫星花 = 7 个逻辑对象（花瓣是同一对象内的路径，不单计），安全余量 3。
3. 鲜花**不注册任何触摸热区**（不写 `hits` 数组），纯视觉层，绝不吞结算按钮点击。

## 1. 触发时机与 660ms 窗口编排（最关键）

**现状锚点**（`core.js`）：`win()` 里 `state.win={t:0}` + `env.audio.play('sfx_win')`；`update()` 里 `state.win.t += dt`；当 `state.win.t > winShrink(260) + winDelay(400) = 660ms` 且无 overlay 时弹结算面板（`state.overlay='result'`）；`render()` 中 `renderPlay()` 先画，`renderResult()` 后画（且 overlay 时先 `hits=[]` 清空页面热区）。

**编排原则**：鲜花复用现有 `state.win.t` 时钟，**不新建第二套计时**；让鲜花在结算面板出现的 **660ms 那一刻正好盛开到峰值**，结算面板自带的半透明遮罩（`COL.mask = rgba(60,45,35,0.24)`）盖下来，形成"鲜花自然退到背景"的衔接，随后鲜花在 660→1000ms 淡出退场。

| 绝对时刻（自 win 起） | 游戏侧事件 | 鲜花侧事件 |
|---|---|---|
| 0ms | `win()`：板件开始收缩、播 `sfx_win`/通关音乐 | 鲜花起苞（孕育，几乎不可见） |
| 0–260ms | 板件收缩 `winShrink` | 主花孕育 + 绽放启动；卫星花错峰弹开 |
| 260–660ms | `winDelay` 等待 | 主花轻弹定格 + 盛开保持；卫星花全部到位 |
| **660ms** | 结算面板出现（`overlay='result'`）、遮罩盖下、星级开始逐颗亮 | 鲜花处于盛开定格 → 随遮罩自然"沉入背景" |
| 660–1000ms | 结算面板淡入、星级弹出 | 鲜花缓慢淡出（不突然消失），不产生第三个视觉焦点 |
| >1000ms | 结算面板稳定可点 | 鲜花销毁，`state.flower = null` |

**为什么不遮挡交互（三重保险）**
1. **层级**：鲜花画在 `renderPlay()` 末尾 / `renderResult()` 之前 → 结算面板与按钮永远在鲜花之上。
2. **热区**：鲜花不写 `hits`；且 overlay 打开时 `render()` 已执行 `hits=[]`，页内热区被清空，按钮热区由 `renderResult()` 独占重建。
3. **构图**：主花落在棋盘中心**偏上**（y≈470），结算面板主体在屏幕中下部，主体视觉不重叠；卫星花弹开半径 ≤190，全部限制在白卡 `B={x:24,y:176,size:702}` 内。

> **假设（请策划确认）**：鲜花与结算面板同屏约 340ms（660–1000ms），此时鲜花已被结算遮罩压暗并淡出，判定为"不干扰"。若主理人希望"鲜花完全结束后才弹结算"，可把弹面板时机从 660ms 延后到 1000ms——但这会让结算出现变慢、可能显"肉"，**本规格不建议**。默认按上表执行。

## 3. 时间轴与关键帧（总时长 1000ms，自 win 起算）

| 阶段 | 时间窗 | 主花状态 | 卫星花状态 | 缓动 |
|---|---|---|---|---|
| **S0 孕育（花苞）** | 0–80ms | 花瓣角度全部闭合（叠成苞）；整体 scale `0.25→0.45`，α `0→0.5` | 未出现（α=0） | `easeOutCubic` |
| **S1 绽放** | 80–360ms | 花瓣角 `0→i×360/7` 展开、瓣长 `0.15L→L`；整体 scale `0.45→1.08`（`easeOutBack` 名义终点，**实际视觉峰值 ≈1.14** 出现在 t≈242ms），α `0.5→1` | 各自 `delay` 后从主花中心冒出、向外弹到目标位并展开花瓣、scale `0→目标 size` | scale `easeOutBack`；角度/位移 `easeOutCubic` |
| **S2 轻弹定格** | 360–560ms | scale `1.08→1.0`，回稳，花瓣微收 | 依次到位收尾（最晚 i5：345+260=605ms 前完成，见下注） | `easeOutCubic` |
| **S3 盛开保持** | 560–660ms | 完全定格；可极缓自转 ≤6°（可选，低端机可关） | 定格 | `linear` |
| **S4 结算衔接淡出** | 660–1000ms | α `1→0`，scale `1→0.90`，原位不动 | 同主花，一起淡出 | `easeIn`（进快出慢，安静退场） |
| **结束** | >1000ms | 销毁：`state.flower=null` | — | — |

> **卫星到位时间校正**：卫星 i 的弹开动画自身时长 240ms（冒出 60 + 弹开 180），i5 延迟 345ms → 到位 345+240=585ms，恰在 S3（560ms）附近收尾、赶在 660ms 结算前盛开，衔接紧密。若个别帧略晚，视觉上仍被 S3 定格覆盖，可接受。

**关键帧速查（主花 scale）**：`t=0 → 0.25` ｜ `80ms → 0.45` ｜ `≈242ms → 1.14（过冲峰）` ｜ `360ms → 1.08（名义终点）` ｜ `560ms → 1.0（稳定）` ｜ `660ms → 1.0` ｜ `1000ms → 0.90, α=0`。
> 说明：`easeOutBack(c1=1.70158)` 在进度 ≈0.58 处达到约 1.10 倍峰值。因此"名义终点 1.08"经该曲线上冲后，实际视觉峰值 ≈1.14，再回落到 1.08（360ms）、最终稳定 1.0（560ms）。程序照抄 §8 的 `0.45 + (1.08-0.45)*easeOutBack(p)` 即得此效果；**不要把 1.14 误当成 bug 去压平**。

## 4. 缓动 Token（全部复用 `geom.js`，禁止新写曲线）

| 用途 | geom.js 函数 | 数学 | 备注 |
|---|---|---|---|
| 孕育、花瓣展开角度、卫星弹开位移 | `G.easeOutCubic(t)` | `1-(1-t)³` | 快进慢停，利落 |
| 绽放 scale 上冲（唯一弹性） | `G.easeOutBack(t)` | `c1=1.70158, c3=c1+1` | 名义终点 1.08，经曲线过冲后视觉峰 ≈1.14，**位移不再叠 back**，避免冲过头 |
| 淡入 α | `G.easeOutCubic(t)` | `1-(1-t)³` | — |
| 淡出 α / scale | `easeIn(t)` = `t*t`（或在 `t` 上跑 `1-G.easeOutCubic(1-t)` 取反） | 慢起快走 | 安静退场，不抢焦点 |
| 盛开保持可选自转 | `linear` | `t` | 每 1000ms ≤6° |

> 注：`geom.js` 无独立 `easeIn` 导出。程序可内联 `function easeIn(t){return t*t;}` 或用 `1-G.easeOutCubic(1-t)`（更缓，二选一，规格默认前者）。

## 5. 动效规格表（核心交付物，程序直接照此实现）

| 元素 | 触发时机 | 属性 | 起始值→结束值 | 时长 | 缓动 | 备注 |
|---|---|---|---|---|---|---|
| 主花·孕育 | `state.win` 建立（t=0） | scale / α / 花瓣角 | `0.25→0.45` / `0→0.5` / 全部闭合成苞 | 80ms | easeOutCubic | 复用 `state.win.t`，不另起时钟 |
| 主花·绽放 | t=80ms | scale | `0.45→1.08`（名义，过冲峰 1.14）`→1.0` | 280ms(涨) + 200ms(收) | easeOutBack（涨）/ easeOutCubic（收） | 全场唯一 overshoot；公式 `0.45+(1.08−0.45)·easeOutBack(p)`，见 §3 说明 |
| 主花·花瓣张开 | t=80ms | 每瓣角度 / 瓣长 | `0→i×360/7` / `0.15L→L` | 280ms | easeOutCubic | 7 瓣七色，顺时针 |
| 卫星花·弹开 | `t=120+i×45ms` | 位移 / scale / α / 花瓣角 | 主花中心→目标点 / `0→size` / `0→1` / 闭合→展开 | 240ms | 位移 easeOutCubic、scale easeOutBack | i=0..5，见 §2 表；峰值触地不叠 back |

| 整束·淡出 | t=660ms（结算面板出现） | α / scale | `1→0` / `1→0.90` | 340ms | easeIn | 与结算遮罩叠加，自然沉入背景 |
| 清理 | t=1000ms | state | `state.flower = null` | — | — | 与 `state.win` 生命周期解耦亦可，见 §7 |

## 6. 层级与交互（务必遵守）

```
render() 绘制顺序（自下而上）：
  [1] 底色 bgDeep
  [2] renderPlay()  → 棋盘白卡 / 目标图案 / 板件 / …… / ★ drawFlowers()  ← 鲜花画这里（renderPlay 末尾）
  [3] if (state.overlay) hits = []            ← 页内热区清空
  [4] renderResult() → 遮罩 / 结算面板 / 星级 / 按钮   ← 永远在鲜花之上
  [5] 页面淡入遮罩
```
- **插入点**：在 `renderPlay()` 函数末尾调用 `drawFlowers(state.flower)`；若程序线更愿意放 `render()` 里，则必须放在 `renderPlay()` 之后、`if(state.overlay)...renderResult()` 之前。
- **绝不在 `renderResult()` 之后画鲜花** —— 那会盖住结算按钮。
- **热区**：`drawFlowers()` 内不调用任何 `hits.push(...)`。按钮热区只在 `renderResult()` 中注册。
- **触摸**：鲜花播放期间若玩家点击，因 overlay 尚未打开（<660ms）会命中.play 页热区——但 `win()` 后 `state.running=false`、`handlePlayDown` 已有 `if(state.win) return`（core.js:811），不会误操作板件。安全。

## 7. 状态机接口建议（给程序线 · 韦码农）

**推荐方案：单时钟 + 纯函数推导**（与现有 `state.win.t` 风格一致，无花瓣数组同步问题，重放 = t 归零）。

```js
// ① win() 内，与 state.win 一起初始化（core.js:340 附近）：
state.win   = { t: 0 };
state.flower = { t: 0 };          // ★ 新增：鲜花动效时钟，单位 ms

// ② update(dt) 内推进（core.js:923 的 state.win 块附近）：
if (state.flower) {
  state.flower.t += dt;
  if (state.flower.t > FLOWER.total) state.flower = null;  // FLOWER.total = 1000
}

// ③ renderPlay() 末尾绘制（纯函数，无副作用、不写 hits）：
if (state.flower) drawFlowers(ctx, state.flower.t, FLOWER_LAYOUT);
```

**建议新增常量**（放 `config.js`，命名 `FLOWER`，与 `ANIM` 平级；数值即本规格值，程序可调）：

```js
FLOWER: {
  total: 1000,
  budEnd: 80, bloomEnd: 360, settleEnd: 560,
  overlayAt: 660,              // 与 ANIM.winShrink + ANIM.winDelay 保持一致
  fadeEnd: 1000,
  peakScale: 1.08,
  main: { x: 375, y: 470, petals: 7, L: 64 },
  satDelay: 45, satStart: 120, satDur: 240, satDist: 170,
  colors: ['#FF8A5B','#4FA8E0','#63C88B','#A87BE8','#D96A9B','#FFC53D','#3FB8B0']
}
```

- **布局表 `FLOWER_LAYOUT`**：6 朵卫星花的方向角/目标点/颜色/大小/延迟按 §2 表写为常量数组（纯数据，可放 config）。目标点也可由 `x=375+dist·cos(a)`、`y=470+dist·sin(a)·0.82` 现算。
- **生命周期**：`state.flower` 在 `t>1000` 自动置 null；`setupLevel()`（`core.js:212/253` 已有重置 `state.win/result/overlay` 的地方）建议也一并 `state.flower=null`，保证切关重入干净。
- **重放/复现**：把 `state.flower.t = 0` 即可原地重播（演示页用的就是这招）。
- **降级开关**：读 `state.reduceMotion`（若程序线有此标志，则走 §9 降级分支）。

**绘制函数签名建议**：`drawFlowers(ctx, t, layout)` —— 只依赖 `t`，不读 `state` 其他字段，方便单测与演示页复用同一套算法。

## 8. 花瓣 Canvas 绘制指引（零素材，程序照画）

**单瓣路径**（以花心为原点，花瓣朝 −Y 即屏幕上方，绘制后 `ctx.rotate(i×2π/n)` 排布）：

```js
// len = 瓣长, w = len * 0.42 （最大半宽）
ctx.beginPath();
ctx.moveTo(0, 0);
ctx.quadraticCurveTo(-w, -len * 0.55, 0, -len);  // 左边 → 瓣尖
ctx.quadraticCurveTo( w, -len * 0.55, 0, 0);     // 瓣尖 → 右边 → 花心
ctx.closePath();
ctx.fillStyle = color; ctx.fill();
// 层次：同色加深 12% 描边 1.5px（不用 shadowBlur，省性能）
```

- **绽放中的瓣长**：`lenNow = L * (0.15 + 0.85 * easeOutCubic(bloomP))`，`bloomP` 为 S1 进度。
- **绽放中的瓣角**：第 i 瓣当前角 `= (i * 2π/n) * easeOutCubic(bloomP)` → 从"全部叠合"旋开到等分放射，这就是"花苞→绽放"的视觉本体。
- **花心**：`ctx.arc(0,0,0.22L)` 填 `#FFC53D`，再 `arc(0,0,0.09L)` 填白；跟随整花 scale。
- **整花 transform**：`ctx.translate(cx,cy); ctx.rotate(spin); ctx.scale(s,s); ctx.globalAlpha=a;` 后画各瓣 + 花心，`ctx.restore()`。
- **卫星花弹开位置**：`cx = main.x + (target.x-main.x) * easeOutCubic(moveP)`，`cy` 同理；`moveP` 从各自 `delay` 起算、240ms 内 0→1。
- **性能**：整束 7 花共 37 条花瓣路径 + 7 花心， Canvas 单次重绘完成，**不开 filter/shadowBlur**，低端机无压力。

## 9. 性能与降级

| 项 | 策略 |
|---|---|
| 帧率 | 全程走现有 `frame()` rAF；单帧仅 44 条简单路径，无合成层、无重排；目标 60fps，低端机 ≥30fps |
| 粒子 | **不额外做粒子系统**；"飞散感"由卫星花弹开承担，粒子数 = 0 |
| 活动对象 | 7 个（1 主 + 6 卫星），上限 10，安全 |
| 描边层次 | 用同色加深 12% 的 1.5px 描边代替 `shadowBlur`，避免高斯模糊开销 |
| 减少动效降级 | 若 `state.reduceMotion === true`：**跳过 S0–S4**，仅在结算面板出现时画一个静态小花图标（1 朵、7 瓣、scale 0.9、α 0→1 用 200ms 淡入后保持至面板关闭或直接不画）——二选一由程序线定，默认"直接不画"，只保留音乐反馈 |
| 低端机降级（可选） | 帧率持续 <40fps 时，卫星花 6→3（取 i=0/2/4）、关可选自转、关描边；主花绽放保留（核心反馈不能砍） |
| 砍动画顺序 | 时间紧先砍：自转 → 卫星花 → 描边层次；**主花绽放必须保留**（这是 A4 的核心反馈） |

## 10. 与音效的时间点建议（给音效线 · 余听声，最终以 A4b 音乐规格为准）

| 时刻 | 视觉事件 | 音频对齐建议 |
|---|---|---|
| 0ms | 鲜花起苞、板件开始收缩 | 现有 `sfx_win`（t=0 已播）或 A4b 新通关音乐**第 1 个音**在此起；两者不要叠成两个"叮" |
| ≈242ms | 主花 scale 冲到视觉峰值 ≈1.14（绽放顶点） | 建议音乐在此处安排一个**旋律高音/重音**（点缀"叮"），与视觉峰值同帧，成就感最强（对齐点取 230–260ms 区间即可，无需精确） |
| 120/165/…/345ms | 6 朵卫星花依次弹开 | 若音乐是分解和弦/琶音，可让 6 个音头大致对齐这 6 个延迟，形成"花瓣开一颗、音符响一颗"；非必须 |
| 660ms | 结算面板出现、鲜花开始淡出 | 音乐进入收尾/延音，不要在此再起新强拍，避免与星级逐颗亮（starStep=120ms）的音效打架 |

> 已同步给音效线：核心对齐点是**0ms 起音 + 242ms 峰值重音**。A4b 采用纯 Web Audio 合成（无文件、双端一致）时，程序线把这段合成参数写进 `_win` 分支即可，与鲜花共用 `state.win.t` 时间基准。

## 11. 与美术 / 策划的待确认项（本版零素材，仅列假设）

- **零素材确认**：本动效不需要任何新图片；花瓣、花心、层次全部 Canvas 绘制。美术线本版预算 0，无需出图。
- **颜色取值**：采用 team-lead 给的七巧板 7 色；若策划希望四巧板关卡只出现 4 色，请明确——**当前默认恒定 7 色**（庆祝一致性优先）。
- **假设 1**：鲜花与结算面板同屏 340ms（已被遮罩压暗并淡出），判定不干扰交互。见 §1 注。
- **假设 2**：主花位置固定在棋盘中心偏上 (375,470)，不随目标图案的实际 bbox 变化——图案形状各异，固定位置更可控。如需"花从图案正中心开出"，请策划确认，程序可按图案 bbox 中心改。
- **假设 3**：四巧板 / 七巧板两套模式用**同一套鲜花动效**（不区分模式），符合"每关拼成功都给鲜花"的需求原文。
